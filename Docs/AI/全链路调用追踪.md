# 怪物 AI 全链路调用追踪

> 目的：把「数据从哪来 → 一帧怎么决策 → 一刀怎么打到人」三段链路，按**类 + 方法 + 行号**完整串起来。
> 行号基于 2026-10-22 的工作区版本，改动后可能偏移，以方法名为准。

---

## 一、总览：三段链路

| 段 | 起点 | 终点 | 触发频率 |
|---|---|---|---|
| 数据装配 | `Data/Tables/*.xlsx` | `MonsterAIDefinition` 对象 | 每只怪生成一次 |
| 帧内决策 | `EnemyBrain.Update()` | 执行器 `Start()` | 每帧（有守卫） |
| 命中结算 | 执行器 `Tick()` | `CombatAttribute.TakeDamage()` | 每招一次 |

---

## 二、数据链路

### 2.1 五阶段

| 阶段 | 位置 | 产出 |
|---|---|---|
| ① Excel 源表 | `Data/Tables/*.xlsx` | 人可编辑的行 |
| ② 导出 | `Data/Excel2Json.cmd` | `Data/Data/*.txt`（JSON 文本） |
| ③ 解析分组 | `DataManager.Load()` | 5 个字段，其中 4 个是 `Dictionary<int, List<T>>` |
| ④ 装配 | `Repository.TryGet() → Build()` | 一个 `MonsterAIDefinition` |
| ⑤ 注入 | `EnemyBrain.ConfigureRuntime()` | 4 个组件被配置 |

### 2.3 txt → DataManager 字段

| txt 文件 | 字段 | 类型 | 排序 |
|---|---|---|---|
| `MonsterAI.txt` | `MonsterAICores` | `Dictionary<int, MonsterAICoreDefine>` | 无（Key 就是 TID） |
| `MonsterAbility.txt` | `MonsterAbilitiesByTid` | `Dictionary<int, List<MonsterAbilityDefine>>` | **不排序** |
| `MonsterBehavior.txt` | `MonsterBehaviorsByTid` | 同上 | `OrderBy(RuleIndex)` |
| `MonsterBehaviorCondition.txt` | `MonsterBehaviorConditionsByTid` | 同上 | `OrderBy(RuleIndex, ConditionIndex)` |
| `MonsterAnimation.txt` | `MonsterAnimationBindingsByTid` | 同上 | `OrderBy(BindingIndex)` |

**关键点**：txt 的外层键是行号 `Key`，不是 `TID`。除 `MonsterAI` 外，其余四张表都靠 `GroupBy(item => item.TID)` 重建索引。

### 2.4 两个部署隐患

1. `DataManager` 用相对路径 `Data/Data/`，靠进程工作目录解析。编辑器下可用，打包成 exe 后大概率失效。
2. `DataManager` 构造函数里直接 `Load()`，抛异常会发生在静态初始化路径上，排查时容易看到 "TypeInitializationException" 而不是真实原因。

### 3.2 黑板字段（感知与决策之间唯一的数据契约）

| 字段 | 谁写 | 谁读 |
|---|---|---|
| `Target` | `EnemyPerception.Tick` | `has_target`、`EnterChase`、执行器 |
| `DistanceToTarget` | `EnemyPerception.Tick` | `CanActivate` 的距离判定 |
| `CanSeeTarget` | `EnemyPerception.Tick` | 目前未被读（预留） |
| `HpRatio` | `RefreshHpRatio` / `OnDamaged` | `hp_below` |
| `LastHitTime` | `OnDamaged` | `recently_hit` |

### 3.3 三个容易忽略的点

1. **决策不是每帧都跑**。死亡 / 硬直 / 正在出招三种情况提前 `return`，所以决策频率 = 空闲帧的帧率。
2. **`Select` 里是 `continue` 不是 `break`**。规则命中但能力放不出来（冷却/距离），会继续试下一条。
3. **决策结果是三元组 + 一个引用**：`(Action, AbilityId, Slot)` + 已解析的 `AbilityDefinition`，`EnemyBrain` 不再查表。

## 四、命中结算链

### 4.1 调用栈

```text
AttackAbilityExecutor.Tick(def, ctx, dt, elapsed)          AttackAbilityExecutor.cs:25
└─ EnemyCombat.PublishAttack(combo, ranged, targetPos)     EnemyCombat.cs:25
   └─ EventBus.Publish(new CharacterAttackHitEvent(...))   静态字典 → 同步 Invoke
      └─ CombatDetector.OnAttackHitTriggered(evt)           CombatDetector.cs:26
         ├─ ComboGroupDict[SubType][ComboIndex] → AttackDefine
         ├─ center = TargetPosition != zero ? TargetPosition : pos + forward*OffsetZ
         ├─ GetTargetLayer(Faction)                        Player → "Monster"，否则 "Player"
         ├─ PerformPhysicsOverlap(center, ...)              :72 → OverlapSphere / OverlapBox
         └─ ProcessHits(hits, ...)                          :98
            ├─ 跳过 null / 已死 / 自己

                     ├─ RefreshHpRatio() + BB.LastHitTime = now

```

### 4.2 两张表的分工（最容易混）

| | 来自 | 决定 |
|---|---|---|
| `AbilityDefinition` | `MonsterAbility` | 什么时候打（`HitDelay`）、要不要打（`MinRange/MaxRange`）、打哪一段（`DamageComboIndex`） |
| `AttackDefine` | `AttackDefine` 表 | 打多大范围（形状 + 参数）、多少倍率（`DmgRate`） |

所以“攻击距离”有两套：能力表决定**会不会选这招**，`AttackDefine` 决定**实际打到谁**。两者不一致就会出现「贴脸打空」或「隔空打到人」。

### 4.3 三个隐藏特性

1. **近战没有追踪**。`PublishAttack` 对近战传 `default`，判定中心退化成 `自己 + forward × OffsetZ`；远程才用发招瞬间的目标快照。两者都不是“命中瞬间的目标位置”，这就是前摇可以躲的原因。
2. **全程同步**。`EventBus.Publish` 直接 `Invoke`，一刀的伤害在同一帧同一调用栈完成；`TakeDamage` 里的死亡事件会在 `ProcessHits` 循环中途回调，多段同时命中时有重入风险。
3. **承伤倍率在 `TakeDamage` 里乘**。`stance` 的 `DamageTakenMultiplier = 0.5` 对所有来源生效，不只是近战。

## 五、一张总表：谁负责什么

| 职责 | 类 | 一句话 |
|---|---|---|
| 每帧调度 | `EnemyBrain` | 守卫 + 决定这一帧要不要决策 |
| 索敌 | `EnemyPerception` | 定时扫描，写黑板 |
| 数据载体 | `EnemyBlackboard` | 5 个字段，感知与决策的唯一契约 |
| 规则判定 | `BehaviourRuleSelector` | 第一条全真的规则胜出 |
| 条件求值 | `BehaviorConditionRegistry` | 6 个注册的委托 |
| 能力调度 | `EnemyAbilityRuntime` | 索引、冷却、记账、执行器生命周期 |
| 招式行为 | `IAbilityExecutor` 的 7 个实现 | 只管"这一次"的过程 |
| 攻击发布 | `EnemyCombat` | 把语义转成事件 |
| 事件分发 | `EventBus` | 静态字典，同步 |
| 命中判定 | `CombatDetector` | 查表 + 物理重叠 + 角度过滤 |
| 数值计算 | `DamageCalculator` | 纯静态公式 |
| 血量与事件 | `CombatAttribute` | 扣血、发受伤/死亡事件 |
| 数据装配 | `MonsterAIDefinitionRepository` | 四次 join，缓存 |
| 数据加载 | `DataManager` | 读 txt，按 TID 分组 |
