
## 一、系统概述

本系统负责实现游戏中玩家角色的基础移动、镜头控制以及后续战斗动作。角色采用第三人称动作 RPG 的操作方式，以手柄作为主要输入设备，整体操作逻辑参考《只狼》等成熟第三人称动作游戏。

角色控制系统的核心原则是将**输入、角色行为、实际移动、动画表现和事件通知**进行职责分离。输入系统只负责读取玩家操作并产生输入数据；角色控制系统根据当前状态决定角色应该执行的行为；移动控制负责计算角色实际位置和朝向；动画系统负责表现当前角色行为；事件系统负责向其他模块广播已经发生的行为变化。

整个角色动作系统不会一次性开发完成，而是采用“模块化开发、单模块闭环验证”的方式。当前阶段只开发移动功能，在移动功能经过完整验证之后，再依次加入冲刺、跳跃、闪避、攻击、防御、受击和死亡等其他行为。

---

# 二、整体操作设计

游戏采用手柄作为主要输入设备，最终角色操作规划如下：

|手柄输入|功能|所属模块|
|---|---|---|
|LS|角色移动|移动|
|RS|控制摄像机|摄像机|
|R3|锁定/解除锁定目标|锁定|
|RB|冲刺|移动|
|X|普通攻击|战斗|
|RT|防御|战斗|
|B|闪避|闪避|
|A|跳跃|跳跃|
|Y|道具|道具|

本系统当前只启用 `LS` 和 `RS`。其他按键虽然已经确定功能，但在移动模块完成之前不接入任何游戏逻辑。

# 三、角色移动设计

## 3.1 基本移动逻辑

角色采用典型的第三人称相机相对移动方式。

在未锁定目标时，左摇杆的输入方向不是直接对应世界坐标，而是根据当前摄像机的朝向转换成角色的实际移动方向。因此，玩家无论将摄像机旋转到哪个方向，都可以保持“摇杆向上就是朝屏幕前方移动”的操作体验。

其核心关系为：

```text
左摇杆输入
    ↓
获取摄像机当前朝向
    ↓
计算相对于摄像机的移动方向
    ↓
角色移动
    ↓
角色根据移动方向调整朝向
```

这种设计可以保证摄像机旋转之后，角色的移动操作仍然符合玩家直觉。

例如摄像机位于角色身后时，玩家将 LS 向上推动，角色向摄像机前方移动；玩家将 LS 向左推动，角色向摄像机左侧移动。当摄像机旋转到其他方向后，同样的 LS 输入会自动基于新的摄像机方向重新计算。

---

## 3.2 锁定状态

锁定目标属于后续模块，目前不实现。

系统进入锁定状态后，移动逻辑会从“摄像机相对移动”切换为“目标相对移动”。此时 LS 的输入不再只是控制角色相对于镜头的方向，而是控制角色与敌人之间的相对位置。

整体逻辑为：

```text
未锁定：
LS → Camera Relative Movement

锁定：
LS → Target Relative Movement
```

锁定后的移动主要表现为靠近目标、远离目标以及围绕目标左右移动，从而形成适合动作 RPG 战斗的环绕移动方式。

这部分将在基础移动系统稳定之后单独实现，不与当前移动模块混合开发。

# 四、基础移动动画设计

本项目现有角色动画资源中，与基础移动直接相关的资源如下：

```text
Idle_Battle_SwordAndShiled
MoveFWD_Battle_InPlace_SwordAndShield
MoveBWD_Battle_InPlace_SwordAndShield
MoveLFT_Battle_InPlace_SwordAndShield
MoveRGT_Battle_InPlace_SwordAndShield
SprintFWD_Battle_InPlace_SwordAndShield
```

其中 `SprintFWD` 属于冲刺模块，当前阶段不使用。

基础移动阶段只使用以下五个动画：

```text
Idle_Battle
MoveFWD_Battle
MoveBWD_Battle
MoveLFT_Battle
MoveRGT_Battle
```

由于这几个移动动画均为 `InPlace` 类型，因此角色的真实位置移动不由动画本身产生，而是由角色移动控制系统完成。Animator 负责提供视觉上的行走表现，移动控制器负责修改角色在场景中的实际位置。

因此系统形成以下职责关系：

```text
CharacterMovementController
        ↓
负责角色真实移动

Animator
        ↓
负责角色移动动画表现
```

当前阶段不使用 Root Motion。

# 五、基础移动 Animator 状态机

> **Animator 资产约定**:
> - 当前阶段使用项目内已有的 `Assets/Art/Animators/Player_MVP.controller` 作为 Animator 资产,**保留不删除**,也不新建 `CharacterLocomotion.controller`。
> - `Player_MVP.controller` 内部现有的旧 State、旧 Transition 与本阶段设计无关,只作为后续清理对象。它们的结构不代表当前设计。
> - 所有 Animator 状态机修改(删除旧 State、创建 Locomotion Blend Tree、添加 MoveX / MoveY 参数)都在 `Player_MVP.controller` 内部完成。

基础移动阶段不建立大量独立 State，而是采用一个 `Locomotion` 状态作为移动入口。

Animator 的基本结构为：

```text
Entry
  ↓
Locomotion
```

其中 `Locomotion` 使用二维 Blend Tree，根据移动输入在 Idle、前进、后退、左移和右移之间进行连续混合。

Blend Tree 的逻辑方向为：

```text
                 MoveFWD
                    ↑
                    │
MoveLFT ←──────── Idle ────────→ MoveRGT
                    │
                    ↓
                 MoveBWD
```

Blend Tree 使用 `MoveX` 和 `MoveY` 两个 Float 参数。

二者并不是世界坐标，而是表示当前角色移动输入的二维方向：

```text
MoveX：左右
MoveY：前后
```

例如：

```text
LS 回中
→ MoveX = 0
→ MoveY = 0
→ Idle
```

```text
LS 向上
→ MoveY = 1
→ MoveFWD
```

```text
LS 向下
→ MoveY = -1
→ MoveBWD
```

```text
LS 向左
→ MoveX = -1
→ MoveLFT
```

```text
LS 向右
→ MoveX = 1
→ MoveRGT
```

这样可以让 Animator 专注于“角色现在表现出什么移动状态”，而不需要直接处理摄像机和世界坐标。

# 六、基础移动状态机参数

基础移动阶段只创建最必要的两个 Animator 参数：

|参数名称|类型|用途|
|---|---|---|
|`MoveX`|Float|移动左右方向|
|`MoveY`|Float|移动前后方向|

当前阶段不创建攻击、跳跃、闪避等其他参数，也不提前加入与移动无关的 Animator 状态。

后续系统扩展后，再根据实际行为加入对应参数，例如 `Attack`、`ComboIndex`、`JumpCount`、`DodgeDirection` 等。

这样可以确保第一阶段 Animator 结构足够简单，方便理解和验证。

# 七、摄像机系统设计

摄像机采用第三人称跟随模式，摄像机主要负责两个功能：跟随玩家角色，以及根据 RS 输入旋转镜头。

RS 的水平方向负责控制摄像机绕角色旋转，垂直方向负责控制摄像机俯仰。

由于角色采用 Q 版模型，最终摄像机的距离、高度以及俯视角不直接照搬其他游戏，而是根据角色比例和实际战斗场景进行调整。

但是摄像机的视觉表现和角色移动逻辑必须分离。

摄像机负责：

```text
摄像机位置
摄像机旋转
摄像机跟随
摄像机角度限制
```

角色移动系统负责：

```text
角色移动方向
角色移动速度
角色实际位置
角色朝向
```

两者通过摄像机当前的 Forward 与 Right 方向建立联系。

因此：

```text
CameraController
        ↓
提供摄像机方向
        ↓
CharacterMovementController
        ↓
计算角色实际移动方向
```

角色移动系统不直接负责控制摄像机。

# 八、输入系统设计

输入系统使用 Unity Input System，当前只实现移动模块所需要的手柄输入。

> **输入设备约束**:
> - 当前阶段只使用 Gamepad,不接入键盘(不加入 WASD、方向键、鼠标模拟器等任何键盘绑定)。
> - `Edit → Project Settings → Player → Other Settings → Configuration → Active Input Handling` 设为 `Input System Package (New)`,**不**选 `Both`,确保代码中只走 Input System 通路,没有旧 Input Manager 残留。

移动阶段只关心：

```text
LS → Move
RS → Look
```

其中 LS 输出二维向量：

```text
Vector2
```

RS 同样输出二维向量：

```text
Vector2
```

输入系统的职责仅限于读取和整理设备输入，不负责判断角色能不能移动，也不负责修改 Animator 或 Transform。

因此输入系统只产生：

```text
Move Input
Look Input
```

而不会直接执行：

```text
Transform.Translate()
Animator.SetFloat()
```

角色实际行为由后续控制层处理。

# 九、角色移动控制设计

角色移动控制器负责将输入数据转化为实际角色行为，是移动系统的核心执行模块。

其完整数据流为：

```text
手柄 LS
    ↓
Input System
    ↓
Move Vector2
    ↓
Camera Forward / Right
    ↓
计算 Camera Relative Direction
    ↓
CharacterMovementController
    ↓
角色实际位置
+
角色实际朝向
    ↓
Animator MoveX / MoveY
    ↓
Locomotion Blend Tree
```

这里存在两个不同的数据：

**一是实际移动方向。**

它是世界空间中的方向，用于移动角色。

**二是 Animator 使用的移动方向。**

它是二维移动状态数据，用于驱动 Blend Tree。

这样可以避免让 Animator 承担角色移动计算，也避免让移动控制器依赖具体动画名称。

---

# 十、移动事件系统设计

EventBus 在移动阶段同样只处理移动相关事件。

移动属于连续数据，因此 LS 的每一帧输入不能通过 EventBus 进行广播，否则会产生大量高频事件。

错误设计：

```text
每帧 LS 输入
    ↓
MoveEvent
    ↓
EventBus
    ↓
其他系统
```

正确设计是由移动控制器直接处理连续移动数据，而 EventBus 只广播具有明确意义的状态变化。

当前移动模块只规划两个基础事件：

```text
MovementStartedEvent
MovementStoppedEvent
```

例如角色从 Idle 开始移动时：

```text
Idle
 ↓
开始移动
 ↓
MovementStartedEvent
```

角色停止移动时：

```text
Move
 ↓
停止移动
 ↓
MovementStoppedEvent
```

未来动画、音效、脚步、特效等系统可以订阅这些事件，但当前阶段只验证事件是否能够正确产生和接收，不扩展其他系统。

# 十九、开发阶段划分

为了保证 0 基础情况下每一个系统都能够独立理解和验证，整个系统按照以下顺序开发。

**阶段划分原则**: 以"功能模块闭环"为单位,而不是把"输入 / 摄像机 / 事件"拆成独立阶段。基础移动本身天然依赖输入、摄像机、移动控制、动画表现和事件通知,这些子模块必须协同才能验证"角色真的在动"。

---

### 第一阶段：基础移动完整闭环

第一阶段不是一个孤立子模块,而是建立一个**端到端可验证的最小功能闭环**。它一次性完成以下 6 个子模块的实现和验证,**不再拆分为独立的"输入阶段 / 摄像机阶段 / 事件阶段"**:

```text
手柄输入
  ├─ LS → Move（仅 Gamepad,无键盘）
  └─ RS → Look（仅 Gamepad,无键盘）
        ↓
Input System（Input System Package,仅 New 模式）
        ↓
CharacterMovementController
        ↓
Camera Relative Movement（从一开始就是 Camera Relative,不做"先世界坐标再改"的过渡）
        ↓
Player 实际位置 + 实际朝向
        ↓
Animator 参数 MoveX / MoveY
        ↓
Locomotion Blend Tree（在 Player_MVP.controller 内清理后重建）
        ↓
Idle / FWD / BWD / LFT / RGT
        ↓
EventBus
        ↓
MovementStartedEvent / MovementStoppedEvent
```

#### 1.1 验证标准

完成后必须能够用 Gamepad 验证:

> - 推 LS,角色朝摄像机相对方向移动
> - 旋转摄像机后,推动方向仍然符合"摇杆向上 = 屏幕前方"的直觉
> - 松开 LS,角色立即恢复 Idle
> - 推动 / 松开 LS 时,EventBus 分别触发 MovementStarted / MovementStopped
> - Animator 中 MoveX / MoveY 实时反映当前输入
> - Blend Tree 在 5 个 Motion 之间连续混合

#### 1.2 第一阶段不做的事

第一阶段严格不允许处理(留给后续阶段):

```text
Sprint / Jump / Dodge / Lock-On / Attack / Combo / Defend / Hit / Death / AI / Special Animation
```

#### 1.3 后续阶段
