# 10. 阶段三怪物受击与死亡 策划方案

> 承接：`8.阶段二怪物近战攻击闭环策划方案.md`、`9.阶段二手把手实现手册`
> **一句话目标**：让螃蟹从"只会打人"变成"**被打会受击硬直、会死亡**"，并顺带打通玩家受击动画。

---

## 一、目标与范围

### 1.1 目标

打通「**谁掉血谁有反应**」的反馈闭环，端到端验证：

```text
玩家攻击螃蟹 → 螃蟹受击硬直(播 TakeDamage + 打断当前动作)
             → 血量归零 → 播 Die 动画、停止一切(Dead)
玩家被螃蟹咬 → 玩家播 GetHit 受击动画(顺带打通)
```

### 1.2 范围内（本阶段做）

| 项 | 内容 |
| -- | -- |
| 受击事件源 | `CombatAttribute.TakeDamage` 扣血后**发布受击/死亡事件**（区分玩家/怪物阵营） |
| 怪物受击状态 | 新增 `Hit` 状态（打断 + 播 TakeDamage + 硬直） |
| 怪物死亡状态 | 新增 `Dead` 状态（播 Die + 停止感知/移动，终止态） |
| 事件订阅 | `EnemyBrain` 订阅 `EnemyDamagedEvent` / `EnemyDiedEvent` → 切 Hit/Dead |
| 玩家受击动画 | 复用已有 `CharacterFeedback`（事件打通即生效，无需新代码） |

### 1.3 范围外（本阶段严格不做）

```text
├─ 尸体销毁 / 掉落（本阶段尸体保留,CombatAttribute.IsDead 保证不再被打）
├─ 受击击退位移(Knockback 字段已有但本阶段不消费)
├─ 远程攻击 / 缩壳 / 滚动(阶段四)
├─ 受击方向细分(FromDirection 本阶段传 Vector3.zero,阶段四再细化)
└─ 玩家死亡流程(玩家侧已有 CharacterFeedback 播 Die,完整流程后续再做)
```

## 三、核心设计

### 3.1 受击事件源：CombatAttribute 发事件（本阶段第一关键）

**问题**：现在 `CombatAttribute.TakeDamage` 只扣血 + 打日志，**没有任何下游知道"谁挨打了"**，所以怪物不会播受击、玩家也不播 GetHit。

**方案**：`TakeDamage` 扣血后，按阵营发布对应事件：

```text
扣血 → CurrentHp <= 0 ?
     ├─ 是 → 发布死亡事件(CharacterDiedEvent / EnemyDiedEvent)
     └─ 否 → 发布受击事件(CharacterDamagedEvent / EnemyDamagedEvent)
```

**阵营怎么识别**：`CombatAttribute` 在 `Awake` 里 `GetComponent<ICombatEntity>()` 拿到阵营（玩家/怪物都实现该接口，且与 `CombatAttribute` 挂在同一 GameObject）。**无需在 Inspector 手动配置阵营**，自动识别、不漏配。

> 这一步同时打通了玩家受击：`CharacterFeedback` 早已订阅 `CharacterDamagedEvent`/`CharacterDiedEvent`，事件一发，玩家的 `GetHit`/`Die` 动画自动就位。

### 3.2 怪物状态机即"移动锁"（对 4 号策划案的合理简化）

4 号策划案里列了 `EnemyStateController`（照抄 `CharacterStateController`）。但**本阶段明确不引入它**，理由：

- 玩家需要 `CharacterStateController`，是因为 `CharacterMovementController` / `CharacterCombat` / `CharacterJumpController` 是**多个并行组件**，需要一个中央锁协调"现在能不能动/能不能打"。
- 怪物是**单线程状态机**（`EnemyBrain` 每帧只跑一个状态），状态之间天然互斥：`Hit`/`Dead`/`AttackMelee` 状态里 `Stop()` 且不再 `SetDestination`，移动自然被锁死。**状态机本身就是锁。**

> 引入多余的 `EnemyStateController` 反而是过度设计——它和状态机在做同一件事，会造成"两个真相源"。

### 3.3 状态流转

```text
                 Any State（任意状态）
                    │  受击(EnemyDamagedEvent)
                    ▼
                ┌────────┐  硬直结束(还能看到目标)  ┌─────────┐
                │  Hit   ├─────────────────────────►│  Chase  │
                └────────┘  (看不到→ Idle)          └─────────┘

                 Any State（任意状态,最高优先级,不可打断）
                    │  HP=0(EnemyDiedEvent)
                    ▼
                ┌────────┐
                │  Dead  │  ← 终止态,无出口
                └────────┘
```

- `Hit` 硬直用**固定时长**（`HitStunDuration` 默认 0.4s），结束回归 `Chase`/`Idle`。
- `Dead` 进入即 `SetDead(true)` 播 Die，并禁用 `Agent`（移动）与 `Perception`（感知），尸体彻底静止。

### 3.4 数据流（一帧内）

```text
玩家攻击 → CharacterAttackHitEvent → CombatDetector → 螃蟹 CombatAttribute.TakeDamage
    ↓ 扣血
发布 EnemyDamagedEvent（或 EnemyDiedEvent）
    ↓ 同步回调
EnemyBrain.OnDamaged → ChangeState(Hit)   → Stop + PlayTakeDamage + 硬直
EnemyBrain.OnDied    → ChangeState(Dead)  → Stop + SetDead(true) + 禁用 Agent/Perception
```

> 注意 `EventBus.Publish` 是**同步**的：`TakeDamage` 里发事件，`EnemyBrain` 的回调当场执行、当场切状态，链路无延迟。

## 七、潜在风险与应对措施

| # | 风险 | 影响 | 应对 |
| -- | -- | -- | -- |
| 1 | `CombatAttribute` 识别不到 `ICombatEntity`（`GetComponent<接口>` 拿空） | 不发事件 | 确认实体与 `CombatAttribute` 同 GameObject；若接口识别异常，退回用 `GetComponent<CharacterEntity>()/GetComponent<EnemyEntity>()` 二选一 |
| 2 | 事件发布顺序错误（死了还发受击事件） | 受击动画覆盖死亡动画 | `TakeDamage` 里先判 `CurrentHp<=0` 再决定发死亡还是受击，二选一 |
| 3 | 受击打断没生效（怪还在追） | 体验差 | 确认 `EnemyBrain` 正确订阅；`ChangeState` 的 `_initialized` 守卫 |
| 4 | 受击动画抽搐 | Any State 过渡 `Can Transition To Self` 没关 | Animator 里该过渡设 `Can Transition To Self = false` |
| 5 | 死亡后尸体仍被打/移动 | 表现异常 | `DeadState` 禁用 Agent+Perception；`CombatAttribute.IsDead` 已保证不再扣血 |
| 6 | 玩家被咬不播 GetHit | CharacterFeedback 漏挂/引用空 | 已确认 MC19 挂了 CharacterFeedback；若仍无效查 `_animator` 引用 |

## 八、验收标准

### 8.1 阶段三验收（逐条勾选）

1. [ ] 打螃蟹 → Console 打印 `Shell → Hit`，螃蟹停止当前动作、播放 `Take Damage` 动画
2. [ ] 硬直结束 → 螃蟹回 `Chase`（还看得到玩家）继续追
3. [ ] 把螃蟹打死 → Console 打印 `Shell → Dead`，播放 `Die` 动画，尸体不再移动/感知
4. [ ] 玩家被螃蟹咬 → 玩家播放 `GetHit` 受击动画
5. [ ] **回归**：阶段二能力不受影响（螃蟹仍能追、能咬、玩家掉血）

### 8.2 全系统远期验收（阶段四完成后）

> 螃蟹能追、能近战、能远程、残血缩壳、被打断、会死；换怪只换动画、决策零改动。
