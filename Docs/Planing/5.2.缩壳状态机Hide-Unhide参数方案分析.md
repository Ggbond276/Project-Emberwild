# 5.2 缩壳状态机：Hide / Unhide 参数方案分析

> 承接 `4.ARPG 怪物AI与状态机系统策划方案.md`、`5.小螃蟹Animator搭建操作手册.md`、`5.1.子状态机连线详解.md`
> **起因**：质疑"缩壳为什么同时用 `IsHidden`(Bool) 和 `Unhide`(Trigger) 两个参数"。
> **结论先行：质疑成立。缩壳只用 `IsHidden` 一个 Bool 就够。`Unhide` 已从本方案中移除。**

---

## 一、结论速览

| 问题 | 结论 |
| --- | --- |
| 单个 `IsHidden` 够不够？ | **够**，而且是唯一稳妥的做法 |
| 两个参数是否多余？ | **是**。`Unhide` 没有携带 `IsHidden` 之外的任何信息 |
| 循环问题是否存在？ | **存在**，但要精确定位：循环**不在** Hide↔Unhide 之间，而在"出壳回到 Locomotion 之后" |
| 如何解决？ | **让 `IsHidden` 成为唯一真相源**，删掉 `Unhide` 触发器 |

---

## 二、两套方案对照

### 方案 A：两参数（原方案，已废弃）

```text
参数：IsHidden (Bool) + Unhide (Trigger)
外层：Locomotion → Hide        : IsHidden == true
内层：Hide → Unhide            : Unhide (Trigger)
内层：Unhide → Exit            : Has Exit Time
外层：[Reaction] → Locomotion  : 无条件
代码：ExitHide() → IsHidden = false + SetTrigger("Unhide")
```

### 方案 B：单参数（现行方案）✅

```text
参数：IsHidden (Bool)
外层：Locomotion → Hide        : IsHidden == true
内层：Hide → Unhide            : IsHidden == false
内层：Unhide → Exit            : Has Exit Time
外层：[Reaction] → Locomotion  : 无条件
代码：EnterHide() → IsHidden = true
      ExitHide()  → IsHidden = false
```

## 三、循环到底发生在哪（逐步推演）

### 3.1 方案 A 的失效路径

| 步 | 事件 | 此时 IsHidden | 当前状态 |
| --- | --- | --- | --- |
| 1 | 螃蟹缩壳 | `true` | Hide（循环） |
| 2 | AI 请求出壳，只设了 `Unhide` 触发器（`IsHidden` 没被置回） | `true` | Hide |
| 3 | `Hide → Unhide` 命中，播 `Hide to Idle` | `true` | Unhide |
| 4 | `Unhide → Exit` → 外层 → `Locomotion` | `true` | Locomotion |
| 5 | **`Locomotion → Hide` 因为 `IsHidden == true` 立刻命中** | `true` | Hide |
| 6 | 而 `Unhide` 触发器已被消耗，`Hide → Unhide` 不再触发 | `true` | Hide（卡住） |
| 7 | 若 AI 每帧继续请求出壳（反复 `SetTrigger`） | `true` | **Hide→Unhide→Locomotion→Hide→… 死循环** |

**根因**：循环不是因为"Hide 和 Unhide 之间画了环线"，而是因为
**`IsHidden` 与 `Unhide` 在描述同一件事，一旦不同步，外层 `Locomotion → Hide` 这条线就会把螃蟹重新拉回去。**

> 补充：方案 A 若严格保证"两个参数每次都一起设"，理论上也能跑。但它把**一个概念**拆成了**两个必须永远同步的旋钮**——这是自找的脆弱点，属于"能跑但不该这么设计"。

### 3.2 方案 B 的推演

| 步 | 事件 | 此时 IsHidden | 当前状态 |
| --- | --- | --- | --- |
| 1 | 螃蟹缩壳 | `true` | Hide |
| 2 | AI 请求出壳 → `IsHidden = false` | `false` | Hide |
| 3 | `Hide → Unhide`（条件 `IsHidden == false`）命中 | `false` | Unhide |
| 4 | `Unhide → Exit` → 外层 → `Locomotion` | `false` | Locomotion |
| 5 | `Locomotion → Hide` 需要 `true`，**不命中** | `false` | Idle ✅ |
| 6 | 想再缩壳 → `IsHidden = true` | `true` | Hide ✅ |

**一个布尔同时表达了两件事**：
- "现在要不要**待在** Hide"（外层 `Locomotion → Hide`）
- "现在要不要**离开** Hide"（内层 `Hide → Unhide`）

这两件事本来就是同一件事的两面，所以**不可能自相矛盾**，也就没有循环。

## 四、附带发现：`Unhide` 还有"触发器挂起"的坑

`Trigger` 是**一次性、且会挂起**的：如果它在螃蟹**不在 Hide 状态**时被设置（例如螃蟹正在攻击、或者已经死了），它不会被消耗，会一直挂着。等螃蟹**下次进入 Hide** 时，`Hide → Unhide` 会立刻触发 —— 表现为"**刚缩壳就自己弹出来**"。

`Bool` 没有这个问题：它描述的是"**当前是不是这个状态**"，而不是"**有一个待办事件**"。

---

## 五、统一原则：Bool 管"持续状态"，Trigger 管"瞬时事件"

这条原则同时解释了为什么 `Die` 触发器也是多余的（4 号方案里列了它，实际过渡只用了 `IsDead`）：

| 参数 | 类型 | 理由 |
| --- | --- | --- |
| `Speed` | Float | 持续量（0/0.5/1） |
| `IsDead` | **Bool** | 死亡是**持续状态**（死了就一直死），`IsDead == true` 即可，不需要 `Die` 触发器 |
| `IsHidden` | **Bool** | 缩壳是**持续状态** |
| `Attack` / `ProjectileAttack` / `CastSpell` / `Roll` | Trigger | **瞬时动作**，播完即结束 |
| `TakeDamage` | Trigger | **瞬时事件**（受击是"发生了一下"） |

> **判定口诀**：这个参数描述的是"**一个状态**"还是"**发生了一次**"？
> 状态 → `Bool` / `Float`；发生了一次 → `Trigger`。
> `IsDead` 就是标准的单 Bool 方案，`IsHidden` 与它保持同一范式。

**最终参数：8 个**（原来 9 / 10 个，去掉 `Unhide` 与 `Die`）。

## 六、你当前界面要怎么改（3 步）

1. 选中 `Hide → Hide to Idle` 这条箭头（Inspector 里 `Conditions` 现在是 `Unhide`）：
   - 删掉 `Unhide` 条件；
   - 添加 `IsHidden` 条件，并把它的值设为 **false**（勾选框取消，显示 `false`）。
2. 确认外层 `Locomotion → Hide` 的条件是 `IsHidden` = **true**。
3. 回到 Parameters 面板，**删掉 `Unhide` 参数**。

改完跑一遍：手动拨 `IsHidden`（`true` → 缩壳；`false` → 出壳回 Idle），确认不会反复弹缩。

## 七、自检

- [ ] Parameters 里**没有** `Unhide`（也没有 `Die`）
- [ ] `Locomotion → Hide` 条件是 `IsHidden == true`
- [ ] `Hide → Unhide` 条件是 `IsHidden == false`
- [ ] `Unhide → Exit` 勾了 `Has Exit Time`
- [ ] 反复切换 `IsHidden` true/false，不出现"刚缩壳就弹出"，也不出现死循环
