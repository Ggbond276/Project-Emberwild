# 6. 阶段一手把手实现手册 —— 让螃蟹"活过来"

> 配套：`4.ARPG 怪物AI与状态机系统策划方案.md`（阶段一）、`5 / 5.1 / 5.2`（Animator）  
> **本阶段目标**：螃蟹能**发现玩家 → 追过来 → 动画随速度切换 → 丢失目标回 Idle**。  
> **学习方式**：每个文件先讲"**为什么这么设计**"，再给**完整代码**，最后逐段拆解 + **检查点**。请严格按顺序做，每步都能单独验证。

## 0. 先看清全局：本阶段到底在造什么

回顾三层架构（4 号方案第 3.4 节）：

```text
决策层   EnemyBrain + IEnemyState + IdleState / ChaseState   ← 本阶段新写
执行层   CustomNavAgent（已有）                              ← 本阶段复用，不改
表现层   EnemyAnimator → Shell.controller（已完成）           ← 本阶段新写"翻译官"
```

**一句话**：你上一阶段造的 `Shell.controller` 是一台"只会执行、不会思考"的机器；本阶段要给它装上**眼睛（Perception）+ 大脑（Brain）+ 嘴（Animator）**。

本阶段要新建 **9 个文件**（全放在 `Assets/Scripts/AI/Enemy/`）：

| 顺序 | 文件                     | 类型            | 一句话职责                |
| -- | ---------------------- | ------------- | -------------------- |
| 1  | `EnemyBlackboard.cs`   | 普通类           | 状态之间共享的"黑板"          |
| 2  | `EnemyStateType.cs`    | 枚举            | 状态名单                 |
| 3  | `IEnemyState.cs`       | 接口            | 状态类的统一契约             |
| 4  | `EnemyAnimator.cs`     | MonoBehaviour | 把语义指令翻译成 Animator 参数 |
| 5  | `EnemyPerception.cs`   | MonoBehaviour | 视野扫描 → 写黑板           |
| 6  | `EnemyEntity.cs`       | MonoBehaviour | 数据桥接（读数据表）           |
| 7  | `EnemyBrain.cs`        | MonoBehaviour | 决策核心（唯一状态切换入口）       |
| 8  | `States/IdleState.cs`  | 状态类           | 待机                   |
| 9  | `States/ChaseState.cs` | 状态类           | 追击                   |

> **为什么先写黑板和接口？** 因为 `EnemyBrain` 要引用它们。写代码的顺序 = **被依赖的先写**，这样每一步都不会编译报错。

## 步骤 4：开始写代码（核心）

### 4.1 `EnemyBlackboard.cs` —— 状态之间的"共享内存"

**为什么需要它？** 因为 `IdleState` 和 `ChaseState` 都需要知道"目标在哪、能不能看到"。如果每个状态自己去扫、自己去算，就会出现多份重复代码且数据不同步。**黑板 = 感知层写一次，所有状态读。**

新建 `Assets/Scripts/AI/Enemy/EnemyBlackboard.cs`：

```csharp
using UnityEngine;

namespace Emberwild.AI.Enemy
{
    /// <summary>
    /// 怪物黑板 —— 状态之间共享的"内存"。
    ///
    /// 职责:
    /// - 存放所有状态都要读的数据(目标/距离/感知结果/血量比例)。
    /// - 由感知层写,由状态层读。
    ///
    /// 严格不做:
    /// - 不持有任何组件引用(它只是一个数据袋子)。
    /// - 不写任何逻辑(没有方法)。
    /// </summary>
    public class EnemyBlackboard
    {
        /// <summary>当前锁定的目标(玩家)。</summary>
        public Transform Target;

        /// <summary>到目标的距离(没目标时是 float.MaxValue)。</summary>
        public float DistanceToTarget = float.MaxValue;

        /// <summary>感知结果:当前是否看得到目标。</summary>
        public bool CanSeeTarget;

        /// <summary>血量比例 0~1(阶段四"残血缩壳"要用)。</summary>
        public float HpRatio = 1f;

        /// <summary>上次攻击时间(阶段二算冷却用)。</summary>
        public float LastAttackTime;
    }
}
```

**讲解**：

- 它是**普通 C# 类**，不是 `MonoBehaviour` —— 因为它不需要挂在 GameObject 上，只是一个数据容器。
- `float.MaxValue` 是"没有目标"时的哨兵值，比 `0` 安全（`0` 会被误判成"贴着目标"）。

### 4.2 `EnemyStateType.cs` —— 状态名单

```csharp
namespace Emberwild.AI.Enemy
{
    /// <summary>
    /// 怪物状态名单。阶段一只有两个,后续阶段往这里加。
    /// </summary>
    public enum EnemyStateType
    {
        Idle,      // 待机
        Chase,     // 追击
        // 阶段二: AttackMelee
        // 阶段三: Hit, Dead
        // 阶段四: AttackRanged, Hide, RollChase
    }

```

**为什么要单独一个枚举？** 因为 `EnemyBrain` 的字典、状态切换入口都用它做 key。集中一处，加状态只改这一个文件。

### 4.3 `IEnemyState.cs` —— 状态类的统一契约

**为什么用"接口 + 状态类"而不是一个大 `switch`？**  
用 `switch` 时，每加一个状态都要回到 `EnemyBrain.Update` 里改代码，越改越长；用状态类时，**新增状态 = 新增一个类 + 注册一行**，`EnemyBrain` 一个字都不用动。这就是"商业开发"和"能跑就行"的区别。

```csharp
namespace Emberwild.AI.Enemy
{
    /// <summary>
    /// 所有怪物状态的统一契约。
    /// 三个生命周期:进入 / 每帧 / 退出。
    /// </summary>
    public interface IEnemyState
    {
        /// <summary>进入该状态时调用一次。</summary>
        void OnEnter(EnemyBrain brain);

        /// <summary>处于该状态时每帧调用。</summary>
        void OnUpdate(EnemyBrain brain);

        /// <summary>离开该状态时调用一次。</summary>
        void OnExit(EnemyBrain brain);
    }
}
```

**讲解**：每个方法都把 `EnemyBrain` 作为参数传进来（而不是在状态类里存一份 `_brain`），这样状态类**完全无状态**，可以安全复用。

### 4.4 `EnemyAnimator.cs` —— 唯一允许碰 Animator 的类

**为什么要有它？** 如果让 `ChaseState` 直接写 `animator.SetFloat("Speed", ...)`，那么以后你把参数名 `Speed` 改成 `MoveSpeed`，就得全项目搜索替换。有了这一层，**调用方只说"我要播什么"，改参数名只改这一个文件**。

> 这就是你 `CharacterAnimator` 的做法，我们**照抄思想**。

```csharp
using Emberwild.Core.AppLog;
using UnityEngine;

namespace Emberwild.AI.Enemy
{
    /// <summary>
    /// 怪物动画播放层 —— 唯一允许接触 Animator 的类。
    ///
    /// 职责:
    /// - 持有 Animator 引用 + 所有参数 Hash。
    /// - 对外暴露语义级方法(SetMoveSpeed / PlayBiteAttack / ...)。
    /// - 调用方只说"播什么",不说"碰哪个 Trigger / Bool / Float"。
    ///
    /// 严格不做:
    /// - 不读 / 不写游戏状态(HP / 距离 / 目标 都在调用方)。
    /// - 不订阅事件总线。
    /// </summary>
    [DisallowMultipleComponent]
    public class EnemyAnimator : MonoBehaviour
    {
        [Header("引用")]
        [Tooltip("怪物 Animator(挂在怪物 GameObject 上)")]
        [SerializeField] private Animator _animator;

        [Header("Float 参数名")]
        [SerializeField] private string _speedParameter = "Speed";

        [Header("Bool 参数名")]
        [SerializeField] private string _isDeadParameter = "IsDead";
        [SerializeField] private string _isHiddenParameter = "IsHidden";

        [Header("Trigger 参数名")]
        [SerializeField] private string _attackTrigger = "Attack";
        [SerializeField] private string _projectileAttackTrigger = "ProjectileAttack";
        [SerializeField] private string _castSpellTrigger = "CastSpell";
        [SerializeField] private string _rollTrigger = "Roll";
        [SerializeField] private string _takeDamageTrigger = "TakeDamage";

        private int _speedHash;
        private int _isDeadHash;
        private int _isHiddenHash;
        private int _attackHash;
        private int _projectileAttackHash;
        private int _castSpellHash;
        private int _rollHash;
        private int _takeDamageHash;

        private void Awake()
        {
            if (_animator == null)
            {
                _animator = GetComponent<Animator>();
            }

            if (_animator == null)
            {
                AppLog.Error("Enemy", "EnemyAnimator: 找不到 Animator 组件, 请在 Inspector 里指定");
                enabled = false;
                return;
            }

            _speedHash = Animator.StringToHash(_speedParameter);
            _isDeadHash = Animator.StringToHash(_isDeadParameter);
            _isHiddenHash = Animator.StringToHash(_isHiddenParameter);
            _attackHash = Animator.StringToHash(_attackTrigger);
            _projectileAttackHash = Animator.StringToHash(_projectileAttackTrigger);
            _castSpellHash = Animator.StringToHash(_castSpellTrigger);
            _rollHash = Animator.StringToHash(_rollTrigger);
            _takeDamageHash = Animator.StringToHash(_takeDamageTrigger);
        }

        // ---------- 状态广播 ----------

        /// <summary>同步移动速度到 Animator,驱动 Locomotion Blend Tree。参数范围 0~1。</summary>
        public void SetMoveSpeed(float normalizedSpeed)
        {
            if (_animator == null) return;
            _animator.SetFloat(_speedHash, normalizedSpeed);
        }

        /// <summary>同步死亡状态(持续状态,用 Bool)。</summary>
        public void SetDead(bool dead)
        {
            if (_animator == null) return;
            _animator.SetBool(_isDeadHash, dead);
        }

        /// <summary>同步缩壳状态(持续状态,用 Bool)。</summary>
        public void SetHidden(bool hidden)
        {
            if (_animator == null) return;
            _animator.SetBool(_isHiddenHash, hidden);
        }

        // ---------- 一次性动作 ----------

        /// <summary>播放近战攻击。</summary>
        public void PlayBiteAttack()
        {
            if (_animator == null) return;
            _animator.ResetTrigger(_attackHash);
            _animator.SetTrigger(_attackHash);
        }

        /// <summary>播放远程攻击。</summary>
        public void PlayProjectileAttack()
        {
            if (_animator == null) return;
            _animator.ResetTrigger(_projectileAttackHash);
            _animator.SetTrigger(_projectileAttackHash);
        }

        /// <summary>播放施法。</summary>
        public void PlayCastSpell()
        {
            if (_animator == null) return;
            _animator.ResetTrigger(_castSpellHash);
            _animator.SetTrigger(_castSpellHash);
        }

        /// <summary>播放滚动冲刺。</summary>
        public void PlayRoll()
        {
            if (_animator == null) return;
            _animator.ResetTrigger(_rollHash);
            _animator.SetTrigger(_rollHash);
        }

        /// <summary>播放受击。</summary>
        public void PlayTakeDamage()
        {
            if (_animator == null) return;
            _animator.ResetTrigger(_takeDamageHash);
            _animator.SetTrigger(_takeDamageHash);
        }
    }
}
```

**讲解**：

- `Animator.StringToHash()` 在 `Awake` 里**预先算好**。每帧用字符串查参数会有性能开销，用 `int` Hash 是零成本。
- 每个 `PlayXxx` 都先 `ResetTrigger` 再 `SetTrigger` —— 防止上一次的残留触发器导致"多播一次"（你 `CharacterAnimator` 里也是这么做的）。
- 参数名全部做成 `[SerializeField]`，这样以后改名字在 Inspector 里改就行，不用碰代码。


**✅ 检查点**：这个文件此刻应该能单独编译通过（它只依赖 `AppLog`）。

### 4.5 `EnemyPerception.cs` —— 眼睛

**为什么独立成类？** 你原来的 `EnemyAI` 把"扫描"和"决策"混在一起。拆开后，`Perception` 只负责**回答"我看得到目标吗"**，不负责**决定"要不要追"**（那是 Brain 的事）。

```csharp
using UnityEngine;

namespace Emberwild.AI.Enemy
{
    /// <summary>
    /// 怪物感知层 —— 负责"看",不负责"想"。
    ///
    /// 职责:
    /// - 定时扫描(不是每帧,省性能) → 找到目标 → 写黑板。
    /// - 提供"丢失目标"的滞后区间,避免边界抖动。
    ///
    /// 严格不做:
    /// - 不决定要不要追(那是 EnemyBrain 的事)。
    /// - 不碰 Animator / 移动。
    /// </summary>
    [DisallowMultipleComponent]
    public class EnemyPerception : MonoBehaviour
    {
        [Header("视野")]
        [Tooltip("能看到玩家的最大距离")]
        [SerializeField] private float _sightRange = 10f;

        [Tooltip("丢失目标距离。比 _sightRange 大一点,形成滞后区间,防止在边界反复切换")]
        [SerializeField] private float _loseTargetRange = 13f;

        [Tooltip("要搜索的目标层级(玩家所在层)")]
        [SerializeField] private LayerMask _targetLayer;

        [Tooltip("雷达扫描间隔(秒)。不需要每帧扫,省性能")]
        [SerializeField] private float _scanInterval = 0.2f;

        private Transform _currentTarget;
        private float _lastScanTime = -999f;

        public Transform CurrentTarget => _currentTarget;

        /// <summary>由 EnemyBrain 每帧调用一次,结果写进黑板。</summary>
        public void Tick(EnemyBlackboard bb)
        {
            // 1. 定时扫描(节流)
            if (Time.time - _lastScanTime >= _scanInterval)
            {
                _lastScanTime = Time.time;
                Scan();
            }

            // 2. 已有目标时,检查是否超出"丢失距离"
            if (_currentTarget != null)
            {
                float dist = Vector3.Distance(transform.position, _currentTarget.position);
                if (dist > _loseTargetRange)
                {
                    _currentTarget = null;      // 追丢了
                }
                else
                {
                    bb.DistanceToTarget = dist;
                }
            }

            // 3. 写黑板(感知层唯一的输出)
            bb.Target = _currentTarget;
            bb.CanSeeTarget = _currentTarget != null;
            if (_currentTarget == null)
            {
                bb.DistanceToTarget = float.MaxValue;
            }
        }

        private void Scan()
        {
            // 以自身为圆心画球形雷达,只过滤目标层
            Collider[] hits = Physics.OverlapSphere(transform.position, _sightRange, _targetLayer);
            if (hits.Length > 0)
            {
                _currentTarget = hits[0].transform;
            }
        }

        /// <summary>编辑器可视化:黄圈 = 视野,橙圈 = 丢失距离。</summary>
        private void OnDrawGizmosSelected()
        {
            Gizmos.color = Color.yellow;
            Gizmos.DrawWireSphere(transform.position, _sightRange);

            Gizmos.color = new Color(1f, 0.5f, 0f);
            Gizmos.DrawWireSphere(transform.position, _loseTargetRange);
        }
    }
}
```

**讲解（这里有两个关键设计）**：

1. **扫描节流**：`_scanInterval = 0.2f` 表示每 0.2 秒才做一次 `Physics.OverlapSphere`。物理查询不便宜，每帧扫 10 只怪会明显掉帧。你原来的 `EnemyAI` 已经懂这个优化，我们保留。
2. **滞后区间（Hysteresis）**：看到用 `_sightRange = 10`，丢失用 `_loseTargetRange = 13`。如果两个值相等，玩家站在 10 米边缘时，螃蟹会**疯狂在"追/不追"之间抖动**。这是 AI 里最经典的坑之一。

**✅ 检查点**：选中螃蟹时，Scene 视图应该能看到黄圈和橙圈。

### 4.6 `EnemyEntity.cs` —— 数据桥接

**为什么不直接用 `CharacterEntity`？** 因为它依赖 `CharacterData SaveData`（存档数据），怪物不需要存档，直接用会**空引用**。所以新写一个只读数据表的版本。

```csharp
using Emberwild.Combat;
using Emberwild.Core.AppLog;
using Emberwild.Define;
using Emberwild.Manager;
using UnityEngine;

namespace Emberwild.AI.Enemy
{
    /// <summary>
    /// 怪物实体 —— 桥接 CharacterDefine 数据表与 CombatAttribute。
    ///
    /// 职责:
    /// - 按 TID 从 DataManager 读配置。
    /// - 把 HP/AD/DEF 注入 CombatAttribute。
    ///
    /// 严格不做:
    /// - 不涉及存档(怪物不需要 CharacterData)。
    /// - 不做伤害计算 / 死亡判定(那是 CombatAttribute 的事)。
    /// </summary>
    [DisallowMultipleComponent]
    [RequireComponent(typeof(CombatAttribute))]
    public class EnemyEntity : MonoBehaviour
    {
        [Header("数据")]
        [Tooltip("对应 Data/Data/CharacterDefine.txt 里的 TID")]
        [SerializeField] private int _tid = 2001;

        [Header("兜底数值(数据表读不到时使用)")]
        [SerializeField] private float _fallbackHp = 100f;
        [SerializeField] private float _fallbackAD = 10f;
        [SerializeField] private float _fallbackDEF = 10f;

        [Header("依赖组件")]
        [SerializeField] private CombatAttribute _combatAttr;

        private CharacterDefine _define;

        public int TID => _define != null ? _define.TID : _tid;
        public string EnemyName => _define != null ? _define.Name : gameObject.name;
        public string SubType => _define != null ? _define.SubType : "None";
        public float MaxHp => _define != null ? _define.HP : _fallbackHp;
        public float BaseAD => _define != null ? _define.AD : _fallbackAD;
        public float BaseDEF => _define != null ? _define.DEF : _fallbackDEF;
        public CombatAttribute Attribute => _combatAttr;

        private void Awake()
        {
            if (_combatAttr == null)
            {
                _combatAttr = GetComponent<CombatAttribute>();
            }
        }

        private void Start()
        {
            LoadDefine();
            _combatAttr.Initialize(MaxHp, MaxHp, BaseAD, BaseDEF);
        }

        private void LoadDefine()
        {
            var dm = DataManager.Instance;
            if (dm != null && dm.Characters != null && dm.Characters.TryGetValue(_tid, out var define))
            {
                _define = define;
                AppLog.Info("Enemy", $"{name} 读取数据表成功: TID={define.TID} HP={define.HP} SubType={define.SubType}");
            }
            else
            {
                AppLog.Warning("Enemy", $"{name} 数据表里找不到 TID={_tid}, 使用兜底数值");
            }
        }
    }
}
```

**讲解**：

- `[RequireComponent(typeof(CombatAttribute))]`：挂这个脚本时 Unity 会**自动补上** `CombatAttribute`，防止你漏挂。
- **兜底数值**：如果数据表没加载（比如 `TestRunner` 的启动流程还注释着），也不会崩，只是用默认值。阶段一不打架，HP 其实用不到，但结构先立好。
- `Initialize(MaxHp, MaxHp, ...)`：第一个是上限，第二个是当前值 —— 出生满血。

**✅ 检查点**：编译应通过。如果报 `DataManager` 找不到，检查 `using Emberwild.Manager;`。

### 4.7 `EnemyBrain.cs` —— 决策核心（本阶段的主角）

**这是整个系统的"大脑"**。它的职责只有三件：① 每帧驱动感知；② 每帧驱动当前状态；③ 提供唯一的 `ChangeState` 入口。

```csharp
using System.Collections.Generic;
using Emberwild.AI.Pathfinding;
using Emberwild.Core.AppLog;
using UnityEngine;

namespace Emberwild.AI.Enemy
{
    /// <summary>
    /// 怪物决策核心 —— 唯一的状态切换入口。
    ///
    /// 职责:
    /// - 持有所有状态实例(字典)。
    /// - 每帧:驱动感知 → 驱动当前状态。
    /// - 提供 ChangeState() 给状态类调用。
    ///
    /// 严格不做:
    /// - 不碰 Animator 参数(通过 EnemyAnimator)。
    /// - 不碰 Rigidbody / Transform(通过 CustomNavAgent)。
    /// - 不算伤害(通过 EnemyCombat,阶段二)。
    /// </summary>
    [DisallowMultipleComponent]
    [RequireComponent(typeof(CustomNavAgent))]
    public class EnemyBrain : MonoBehaviour
    {
        [Header("组件引用")]
        [SerializeField] private CustomNavAgent _agent;
        [SerializeField] private EnemyPerception _perception;
        [SerializeField] private EnemyAnimator _animator;
        [SerializeField] private EnemyEntity _entity;

        [Header("决策参数")]
        [Tooltip("奔跑速度。必须与 CustomNavAgent.moveSpeed 一致,用于把实际速度归一化成 0~1")]
        [SerializeField] private float _runSpeed = 4f;

        [Tooltip("出生时进入的状态")]
        [SerializeField] private EnemyStateType _defaultState = EnemyStateType.Idle;

        /// <summary>黑板:状态之间共享的数据。</summary>
        public EnemyBlackboard BB { get; } = new EnemyBlackboard();

        public CustomNavAgent Agent => _agent;
        public EnemyPerception Perception => _perception;
        public EnemyAnimator Animator => _animator;
        public EnemyEntity Entity => _entity;
        public float RunSpeed => _runSpeed;

        /// <summary>当前速度归一化到 0~1(给 Animator 的 Speed 用)。</summary>
        public float NormalizedSpeed
        {
            get
            {
                if (_agent == null || _runSpeed <= 0.01f) return 0f;
                return Mathf.Clamp01(_agent.VelocityMagnitude / _runSpeed);
            }
        }

        // 状态字典:类型 → 实例
        private readonly Dictionary<EnemyStateType, IEnemyState> _states
            = new Dictionary<EnemyStateType, IEnemyState>();

        private IEnemyState _current;
        private EnemyStateType _currentType;
        private bool _initialized;

        private void Awake()
        {
            // 自动补齐引用(减少 Inspector 手拖出错)
            if (_agent == null) _agent = GetComponent<CustomNavAgent>();
            if (_perception == null) _perception = GetComponent<EnemyPerception>();
            if (_animator == null) _animator = GetComponent<EnemyAnimator>();
            if (_entity == null) _entity = GetComponent<EnemyEntity>();

            // 注册状态(新增状态就在这里加一行)
            _states[EnemyStateType.Idle] = new IdleState();
            _states[EnemyStateType.Chase] = new ChaseState();
        }

        private void Start()
        {
            if (_agent == null)
            {
                AppLog.Error("Enemy", "EnemyBrain: 缺少 CustomNavAgent, 无法移动");
                enabled = false;
                return;
            }
            if (_perception == null)
            {
                AppLog.Error("Enemy", "EnemyBrain: 缺少 EnemyPerception, 螃蟹将无法发现玩家");
                enabled = false;
                return;
            }

            _initialized = true;
            ChangeState(_defaultState);
        }

        private void Update()
        {
            if (!_initialized) return;

            // 1. 感知先跑,更新黑板
            _perception.Tick(BB);

            // 2. 再让当前状态决策
            _current?.OnUpdate(this);
        }

        /// <summary>
        /// 唯一的状态切换入口。重复切到同一状态会被忽略。
        /// </summary>
        public void ChangeState(EnemyStateType type)
        {
            if (_current != null && _currentType == type) return;

            if (!_states.TryGetValue(type, out var next))
            {
                AppLog.Error("Enemy", $"EnemyBrain: 状态 {type} 未注册");
                return;
            }

            _current?.OnExit(this);
            _currentType = type;
            _current = next;
            _current.OnEnter(this);

            AppLog.Info("Enemy", $"{name} → {type}");
        }
    }
}
```

**逐段讲解（重点看这几处）**：

| 代码                                  | 为什么这么写                                             |
| ----------------------------------- | -------------------------------------------------- |
| `Awake` 里自动 `GetComponent`          | 减少 Inspector 手拖漏项。你项目里 `CharacterAnimator` 也是这么做的。 |
| `_states[Idle] = new IdleState();`  | 状态实例**只创建一次**，反复切换不产生 GC。                          |
| `Update` 里"先感知后决策"                  | **顺序不能反**。感知写完黑板，状态才能读到最新数据。                       |
| `if (_currentType == type) return;` | 防止 `OnExit`/`OnEnter` 被无意义地反复调用。                   |
| `TryGetValue` 而不是 `_states[type]`   | 直接索引找不到会抛异常；用 `TryGetValue` 可以给友好日志。               |
| `AppLog.Info(...→ {type})`          | 这就是你的"决策可视化"：Console 里能直接看到螃蟹的状态流转。                |


**✅ 检查点**：此刻会报错"找不到 `IdleState` / `ChaseState`" —— 正常，下一步就写它们。

### 4.9 `States/ChaseState.cs` —— 追击

```csharp
namespace Emberwild.AI.Enemy
{
    /// <summary>
    /// 追击状态:持续把目标的最新坐标下达给寻路组件,并用实际速度驱动跑步动画。
    /// </summary>
    public class ChaseState : IEnemyState
    {
        public void OnEnter(EnemyBrain brain)
        {
            // 进入追击不需要特殊动作,由 OnUpdate 每帧下达目标坐标
        }

        public void OnUpdate(EnemyBrain brain)
        {
            var bb = brain.BB;

            // 目标丢了(被销毁 / 跑出丢失距离) → 回待机
            if (bb.Target == null || !bb.CanSeeTarget)
            {
                brain.ChangeState(EnemyStateType.Idle);
                return;
            }

            // 持续下达最新坐标(A* 内部会按 pathUpdateInterval 节流)
            brain.Agent.SetDestination(bb.Target.position);

            // 用"实际速度"驱动动画:站着不动=0(Idle),全速=1(Run),中间=Walk
            brain.Animator.SetMoveSpeed(brain.NormalizedSpeed);
        }

        public void OnExit(EnemyBrain brain)
        {
            // 离开追击必须刹车,否则螃蟹会"溜冰"
            brain.Agent.Stop();
            brain.Animator.SetMoveSpeed(0f);
        }
    }
}
```

**讲解（关键在 `NormalizedSpeed` 这句）**：

`brain.NormalizedSpeed` = `实际速度 / 奔跑速度`，结果被 `Clamp01` 压到 0~1。这个值直接喂给你 Animator 里的 **1D Blend Tree**（阈值 0 / 0.5 / 1）：

```text
实际速度 0     → Speed = 0    → Idle
实际速度 一半  → Speed = 0.5  → Walk
实际速度 满    → Speed = 1    → Run
```

所以**动画完全不需要"判断现在该播走路还是跑步"** —— 它自己会按速度平滑插值。这就是"决策层决定做什么、表现层决定长什么样"的完美体现。

**✅ 检查点**：9 个文件写完，Unity 应该 **0 报错**。回到 Unity 等它编译完。
