
## 一、阶段目标

建立项目最基础的资源与代码框架，为后续角色、怪物、动画、战斗等系统提供统一基础。

本阶段只做：

```text
项目目录
资源分类
Prefab 基础存放规则
统一资源加载接口
ResourcesManager
基础单例
AppLog
```

暂时不加入 UI、背包、任务等无关系统。

# 四、Resources 目录

当前阶段统一使用 `Resources` 作为运行时 Prefab 的资源来源。

```text
Resources
└── Prefabs
    ├── Characters
    └── Monsters
```

最终形成：

```text
美术资源
   ↓
筛选
   ↓
Prefab制作
   ↓
Resources/Prefabs
   ↓
运行时加载
```

例如：

```text
Resources/Prefabs/Characters/Samurai.prefab
Resources/Prefabs/Monsters/Goblin.prefab
```

后续角色、怪物等实际运行对象优先从这里加载。

# 五、资源加载设计

当前虽然使用 `Resources.Load`，但不让业务代码直接调用：

```csharp
Resources.Load(...)
```

所有资源加载统一经过：

```text
ResourcesManager
```

业务系统只依赖统一的加载接口。

---

# 六、统一 Load 接口

定义统一资源加载抽象：

```text
IResourceLoader
```

其核心思想：

```text
业务层
   ↓
ResourcesManager
   ↓
IResourceLoader
   ↓
具体加载实现
```

当前：

```text
IResourceLoader
       ↓
ResourcesLoader
       ↓
Resources.Load
```

未来可以切换为：

```text
IResourceLoader
       ├── ResourcesLoader
       ├── AssetBundleLoader
       └── AddressablesLoader
```

业务层无需修改：

```text
业务代码
   ↓
ResourcesManager.Load<T>()
```

只改变底层具体 Loader。

# 七、ResourcesManager 职责

`ResourcesManager` 是项目统一资源加载入口。

负责：

```text
对外提供统一 Load 接口
选择当前资源加载方案
管理具体 Loader
```

业务系统不直接依赖：

```text
Resources
AssetBundle
Addressables
```

而统一依赖：

```text
ResourcesManager
```

最终实现：

```text
                ResourcesManager
                       ↓
                IResourceLoader
                       ↓
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
 ResourcesLoader  AssetBundleLoader  AddressablesLoader
```

未来根据项目打包方案切换具体实现。

```
# 九、AppLog 日志系统

建立项目统一日志系统 `AppLog`，用于规范所有模块的日志输出。

日志必须包含：

- 日志等级：Info / Warning / Error
- 所属模块：模块名称
- 日志信息：具体内容

日志格式：

[模块] [日志等级] 信息

例如：

[Input] [Info] Attack Input Received
[Resource] [Warning] Resource not found
[Combat] [Error] Attack state initialization failed
```

## 模块颜色

不同系统模块使用固定颜色，便于在 Unity Console 中快速区分日志来源。

例如：

```
Core        → 蓝色
Input       → 青色
Resource    → 紫色
Gameplay    → 黄色
Combat      → 橙色
AI          → 绿色
Network     → 青绿色
Editor      → 灰色
```

颜色用于表示**日志来源模块**，而不是表示严重程度。

## 日志等级

日志等级保持统一：

```
Info
Warning
Error
```

其中：

```
Info    → 普通运行信息
Warning → 异常但不会阻止运行的问题
Error   → 严重错误
```

日志等级必须有明确的视觉区分。

## 调用方式

项目代码统一使用：

```
AppLog.Info(module, message);
AppLog.Warning(module, message);
AppLog.Error(module, message);
```

例如：

```
AppLog.Info("Input", "Attack Input Received");
AppLog.Warning("Resource", "Prefab not found");
AppLog.Error("Combat", "Attack initialization failed");
```

```
Info / Warning / Error
统一日志格式

```

````
### 这里有一个很重要的设计

**模块颜色和 Error/Warning 不要混为一谈。**

比如：

```text
[Combat] [Error] ...
````

其中：

```
Combat → 告诉你“谁出的”
Error  → 告诉你“有多严重”
```

# 十、本阶段最终结构

```text
                ┌───────────────┐
                │     Art       │
                │ UnityPackage  │
                │ 模型/动画素材  │
                └───────┬───────┘
                        ↓
                  筛选并制作Prefab
                        ↓
                ┌───────────────┐
                │   Resources   │
                │    Prefabs    │
                └───────┬───────┘
                        ↓
                ┌───────────────┐
                │ ResourcesMgr  │
                └───────┬───────┘
                        ↓
                ┌───────────────┐
                │IResourceLoader│
                └───────┬───────┘
                        ↓
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
      Resources      Bundle      Addressables
```

核心原则：

> **资源文件归资源文件，Prefab 归 Prefab，代码归 Scripts；业务代码不直接接触具体加载方案，通过统一 Load 接口实现后续资源方案切换。**

本阶段先保证 `Resources` 方案完整跑通，后续再增加 AssetBundle 和 Addressables 实现。
