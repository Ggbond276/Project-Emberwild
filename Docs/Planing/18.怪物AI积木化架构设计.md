# 18. 怪物 AI 积木化架构设计（重新设计 · v2）

> 取代已删除的旧 18/19/20 号文档。  
> **本设计目标**：把怪物 AI 做成「搭积木」框架——**新建怪物 = 挂通用组件 + 实现专属 Animator + 建一份专属配置资产**，核心代码零改动。

---

## 一、旧方案（已删除）为什么无法"搭积木"

| # | 耦合点                                                                                               | 后果                               |
| - | ------------------------------------------------------------------------------------------------- | -------------------------------- |
| 1 | **Animator 未抽象**：`EnemyAnimator` 的 8 个参数名是 Shell 动画控制器的（`Speed`/`Attack`/`Roll`/`IsHidden`），却叫通用名 | 换 Wolf（参数名不同）直接失效                |
| 2 | **状态类耦合 Shell 动作名**：`AttackMeleeState` 调 `PlayBiteAttack()`（"咬"是 Shell 动作）                        | Wolf 没有"咬"，状态类无法复用               |
| 3 | **EnemyBrain 硬引用具体类型**：`[SerializeField] EnemyAnimator _animator`                                 | 换 `WolfAnimator` 要改 `EnemyBrain` |
| 4 | **配置结构不完整、数据未独立**：感知/移动参数散在组件上，换怪要逐个填 prefab；且"配置"没有做到"结构复用 + 每怪独立实例"的清晰分层                        | 换怪繁琐、易漏、数据互相干扰                   |

## 二、核心设计：三类积木 + 三层复用

### 2.1 三类积木

```text
┌────────────────────────────────────────────────────────────┐
│ ① 通用积木（框架，复用，永远不改）                          │
│    EnemyBrain · EnemyPerception · CustomNavAgent            │
│    EnemyCombat · EnemyEntity                                │
│    + 行为树框架 / 状态机框架 / 黑板（EnemyBrain 内部）        │
├────────────────────────────────────────────────────────────┤
│ ② 特殊积木（每怪单独实现，这是"每只怪的个性"）              │
│    · Animator：实现 IEnemyAnimator 接口                    │
│      ShellAnimator / WolfAnimator / ...                    │
│    · 特殊状态（可选）：实现 IEnemyState + 工厂注册           │
├────────────────────────────────────────────────────────────┤
│ ③ 配置（结构复用，数据独立）                                │
│    EnemyAIConfig 类 = 统一结构（所有怪共有的配置项 + 决策树） │
│    ShellAI.asset / WolfAI.asset = 每怪一份独立实例           │
└────────────────────────────────────────────────────────────┘
```

### 2.2 三层复用（本设计的关键，纠正上一版误解）

| 层            | 是什么                                                                   | 复用 or 独立     |
| ------------ | --------------------------------------------------------------------- | ------------ |
| **通用配置结构**   | `EnemyAIConfig` 类：定义所有怪物共有的配置项（RunSpeed/ViewRange/MeleeRange…）+ 决策树字段 | **复用（一份代码）** |
| **怪物专属配置资产** | `ShellAI.asset`、`WolfAI.asset`：各自的参数值 + 各自的决策树                        | **独立（每怪一份）** |
| **通用运行时代码**  | `EnemyBrain`/`Perception`/`NavAgent`… 读对应怪物的专属配置                      | **复用（一份代码）** |

> **一句话**：复用的是**配置结构**和**运行时代码**，不是**数据**。改 Shell 的 `RunSpeed=3` 绝不影响 Wolf 的 `RunSpeed=6`——因为它们是两份独立资产。

## 三、配置：统一结构 + 每怪独立实例

### 3.1 统一配置结构 `EnemyAIConfig`（所有怪物共用这一份"字段定义"）

```csharp
[CreateAssetMenu(menuName = "AI/EnemyAIConfig", fileName = "EnemyAIConfig")]
public class EnemyAIConfig : ScriptableObject
{
    [Header("感知（所有怪都有）")]
    public float viewRange = 10f;         // 视野范围
    public float loseTargetRange = 13f;   // 丢失目标距离
    public float scanInterval = 0.2f;     // 扫描间隔

    [Header("移动（所有怪都有）")]
    public float runSpeed = 4f;           // 奔跑速度(归一化基准)
    public float moveSpeed = 4f;          // 实际移动速度
    public float turnSpeed = 10f;         // 转向速度
    public float stoppingDistance = 1.2f; // 刹车距离

    [Header("战斗（所有怪都有）")]
    public float meleeRange = 1.6f;       // 近战距离
    public float attackCooldown = 2f;     // 攻击冷却
    public float hitstunDuration = 0.4f;  // 受击硬直

    [Header("特殊能力（可选，无此能力的怪留默认值/不用）")]
    public float rangedMinRange = 4f;     // 远程(仅远程怪)
    public float rangedMaxRange = 8f;
    public float rollSpeed = 8f;          // 滚动(仅滚动怪)
    public float rollDuration = 1f;
    public float rollCooldown = 4f;
    public float rollMinRange = 3f;
    public float rollMaxRange = 7f;
    public float hideHpThreshold = 0.3f;  // 缩壳(仅缩壳怪)
    public float hideDuration = 10f;

    [Header("决策树（每怪独立）")]
    public List<BTNodeDef> decisionTree = new List<BTNodeDef>();
}
```

### 3.2 每怪一份独立实例（数据互不影响）

```text
ShellAI.asset   →  runSpeed=3, viewRange=5, meleeRange=1.6, 决策树(含缩壳分支)
WolfAI.asset    →  runSpeed=6, viewRange=10, meleeRange=2.0, 决策树(无缩壳,含嚎叫分支)
```

- **同一个字段**（`runSpeed`/`viewRange`…）在所有怪身上都存在——这是"结构复用"。
- **各自的数值**互不影响——改 `ShellAI` 不影响 `WolfAI`——这是"数据独立"。
- 新增一只怪 = **新建一份 `EnemyAIConfig` 资产**，在 Inspector 里填它自己的参数 + 决策树。

> 没有"公共配置资产"这种东西——**没有一份会被所有怪共享的配置实例**。有的只是"一份通用的字段定义（类）+ N 份各自独立的资产（实例）"。

## 四、Animator 抽象：接口 + 每怪实现

### 4.1 统一接口 `IEnemyAnimator`（语义化动作，去 Shell 痕迹）

```csharp
public interface IEnemyAnimator
{
    void SetMoveSpeed(float speed);   // 移动(0~1 驱动 Locomotion)
    void PlayAttack();                // 近战攻击
    void PlayRangedAttack();          // 远程攻击
    void SetRoll(bool roll);          // 滚动冲刺(持续状态,Bool)
    void SetHidden(bool hidden);      // 缩壳(持续状态,Bool;无此能力的怪空实现)
    void PlayTakeDamage();            // 受击
    void SetDead(bool dead);          // 死亡
}
```

### 4.2 每怪实现

- **`ShellAnimator`**：现 `EnemyAnimator` 重命名，实现接口（内部翻译成 `Speed`/`Attack`/`Roll`/`IsHidden` 等 Shell 参数）。
- **`WolfAnimator`**：新写，实现接口（内部翻译成 Wolf 自己的动画参数，如 `WolfBite`）。

```csharp
public class ShellAnimator : MonoBehaviour, IEnemyAnimator
{
    [SerializeField] private Animator _animator;
    public void PlayAttack() { _animator.SetTrigger(_attackHash); }   // Shell 的 "Attack"
}
public class WolfAnimator : MonoBehaviour, IEnemyAnimator
{
    [SerializeField] private Animator _animator;
    public void PlayAttack() { _animator.SetTrigger(_wolfBiteHash); } // Wolf 的 "WolfBite"
    public void SetHidden(bool hidden) { /* Wolf 不缩壳,空实现 */ }
}
```

### 4.3 状态类如何复用（只依赖接口）

| 状态类               | 原来调                                                             | 改为调（语义化）             |
| ----------------- | --------------------------------------------------------------- | -------------------- |
| AttackMeleeState  | `PlayBiteAttack()`                                              | `PlayAttack()`       |
| AttackRangedState | `PlayProjectileAttack()`                                        | `PlayRangedAttack()` |
| 其余 6 个状态类         | `SetRoll`/`SetHidden`/`PlayTakeDamage`/`SetDead`/`SetMoveSpeed` | 不变                   |

## 五、EnemyBrain 积木化

```csharp
public class EnemyBrain : MonoBehaviour
{
    [Header("配置（每怪一份专属资产）")]
    [SerializeField] private EnemyAIConfig _config;

    [Header("通用组件")]
    [SerializeField] private EnemyPerception _perception;
    [SerializeField] private CustomNavAgent  _agent;
    [SerializeField] private EnemyCombat     _combat;
    [SerializeField] private EnemyEntity     _entity;

    // 动画:接口引用,不依赖具体 Animator
    [SerializeField] private MonoBehaviour _animator;
    public IEnemyAnimator Animator => _animator as IEnemyAnimator;

    private void Awake()
    {
        // 1. 从 _config 读参数,注入感知/移动组件 + 自身属性
        // 2. 用工厂创建状态 + BTBuilder 从 _config.decisionTree 建决策树
    }
}
```

> 关键变化：`EnemyBrain` 不再持有 `EnemyAnimator` 具体类型，改为 `IEnemyAnimator` 接口；配置引用**一份专属资产**（每怪一份），运行时代码读这份资产、执行行为。

## 六、新怪物搭建流程（架构总览）

```text
第 1 步 挂通用组件   prefab 挂 EnemyBrain + Perception + NavAgent + Combat + Entity
第 2 步 挂专属动画   挂 ShellAnimator 或新写 WolfAnimator(实现 IEnemyAnimator)
第 3 步 建专属配置   新建一份 EnemyAIConfig 资产,填该怪的参数 + 决策树
第 4 步(可选)加状态  若有特有行为,实现 IEnemyState + EnemyStateFactory.Register
第 5 步 配数据       数据表加条目 + 动画控制器(该怪的参数) + prefab 网格
```

**结论**：第 2、4 步是"每怪的个性"（写 Animator / 写特殊状态）；第 1、3、5 步是"搭积木"（挂 + 建专属配置 + 配数据）；核心框架（EnemyBrain/行为树/状态机/黑板/感知/移动/攻击）永远复用。

## 八、验收标准（本设计落地后）

- [ ] `EnemyAnimator` 已重命名为 `ShellAnimator`，且存在统一接口 `IEnemyAnimator`
- [ ] 状态类只依赖 `IEnemyAnimator`，不出现 Shell 专属方法名（`PlayBiteAttack` 等）
- [ ] 存在**一份通用配置结构** `EnemyAIConfig`（含感知/移动/战斗/特殊/决策树字段）
- [ ] `ShellAI.asset` 与 `WolfAI.asset` 是**两份独立资产**，改一方的参数不影响另一方
- [ ] 新建 Wolf：挂通用组件 + 写 `WolfAnimator` + 建 `WolfAI.asset`，`EnemyBrain`/状态机/行为树**零改动**
- [ ] 回归：Shell 的 8 个行为全部正常
