## 一、目标与范围

**目标**:建立角色受击与死亡的基础表现系统,打通「伤害事件 → 扣血 → 受击动画 / 死亡动画」链路。

**本 Stage 只做**:
- 统一角色数据模型:新建 `CharacterData.cs`,作为纯数据容器,承载 HP/IsDead 等运行时属性,兼容 JSON 序列化
- 角色数据管理器:新建 `PlayerDataManager.cs`,继承 `Singleton<PlayerDataManager>`,持有 `CharacterData` 实例,对外提供伤害处理接口
- PlayerFeedback 组件:订阅 PlayerDamagedEvent / PlayerDiedEvent,驱动 Animator
- TestRunner 模拟伤害:空格键手动触发,验证链路

**本 Stage 不做**:
- 敌人 AI / 真实攻击判定
- 格挡减伤 / 霸体
- 方向区分的受击动画(左 / 右 / 前 / 后)
- 死亡后锁定输入(留 7.9)
- 复活 / 起身

## 三、方案审查

### 3.1 架构问题与修正

#### 原设计问题

原策划案将 `PlayerDataManager` 设计为 `MonoBehaviour`,要求:
- 挂载到 Player 预制体上
- TestRunner 通过 `FindGameObjectWithTag` 或 Inspector 拖拽引用

**问题**:
- 每次访问都需要获取引用,增加耦合
- Inspector 拖拽容易出错,运行时引用丢失
- 不符合项目已有的单例设计模式

#### 修正方案

使用项目现有的 `Singleton<T>` 单例基类:

```csharp
public class PlayerDataManager : Singleton<PlayerDataManager>
{
    // 直接通过 PlayerDataManager.Instance 访问
}
```

**优势**:
- 全局唯一访问点,无需场景挂载和引用传递
- 符合项目既有架构
- 访问简单:`PlayerDataManager.Instance.TakeDamage(...)`

### 3.2 类职责与调用关系

```
伤害来源(TestRunner/敌人AI)
        │
        ▼
┌─────────────────────────────┐
│   PlayerDataManager        │  ← Singleton<T>,无需挂载
│   (Singleton)              │
│                            │
│  - 持有 CharacterData 实例  │
│  - TakeDamage():扣血判定死亡 │
│  - 发布事件                 │
└──────────────┬──────────────┘
               │
       ┌───────┴───────┐
       │               │
       ▼               ▼
┌──────────────┐ ┌──────────────┐
│CharacterData │ │ EventBus    │
│(纯数据容器)   │ │ (发布事件)   │
└──────────────┘ └──────┬───────┘
                        │
                        ▼
              ┌──────────────────┐
              │  PlayerFeedback  │  ← MonoBehaviour,挂载Player
              │  (订阅事件)       │
              │  → Animator.SetTrigger() │
              └──────────────────┘
```

| 类 | 类型 | 职责 | 不负责 |
|---|------|------|--------|
| `CharacterData` | 纯 C# 类(可序列化) | 存放角色数据(HP, IsDead 等) | 任何逻辑 |
| `PlayerDataManager` | `Singleton<T>` | 持有数据,处理伤害,发布事件 | 动画驱动,不挂载场景 |
| `PlayerFeedback` | `MonoBehaviour` | 订阅事件,驱动 Animator | 伤害计算 |
| `Animator` | Unity 资源 | 状态机:Locomotion ↔ GetHit ↔ Death | - |

### 3.3 JSON 存档兼容性

**CharacterData 设计**:

```csharp
[System.Serializable]
public class CharacterData
{
    public float MaxHp = 100f;
    public float CurrentHp = 100f;
    public bool IsDead = false;
    // ...其他字段
}
```

**存档/读档接口**:

| 方法 | 用途 |
|------|------|
| `PlayerDataManager.GetData()` | 获取 CharacterData 快照,供 JSON 序列化 |
| `PlayerDataManager.LoadData(CharacterData)` | 加载反序列化后的数据 |

**序列化示例**(未来存档系统使用):

```csharp
// 存档
string json = JsonUtility.ToJson(PlayerDataManager.Instance.GetData());
File.WriteAllText(path, json);

// 读档
string json = File.ReadAllText(path);
var data = JsonUtility.FromJson<CharacterData>(json);
PlayerDataManager.Instance.LoadData(data);
```

**注意事项**:
- Unity JSONUtility 只能序列化 public 字段和标记了 `[Serializable]` 的类
- CharacterData 不是 MonoBehaviour,可以直接序列化
- 存档系统不纳入本 Stage,仅预留接口

### 3.4 数据流

```
按空格
   ↓

   ↓

   ↓
```

### Step 7.8.2 创建 PlayerDataManager.cs

**文件**:新建 `Assets/Scripts/Character/PlayerDataManager.cs`

```csharp
using Emberwild.Core.AppLog;
using Emberwild.Core.Events;
using Emberwild.Core.Singleton;
using UnityEngine;

namespace Emberwild.Character
{
    /// <summary>
    /// 角色数据管理器 — 全局单例,持有 CharacterData 实例,处理伤害逻辑,发布事件。
    ///
    /// 职责:
    /// - 全局唯一实例,通过 Singleton 模式访问,无需场景挂载
    /// - 持有 CharacterData 实例
    /// - TakeDamage():扣血,判断死亡,发布对应事件
    /// - ResetHealth():重置 HP(供测试/复活用)
    /// - 提供 CurrentHp / MaxHp / IsDead 属性访问
    /// - 提供 GetData() / LoadData() 供存档系统使用
    ///
    /// 不做:
    /// - 不做动画驱动(PlayerFeedback 负责)
    /// - 不做 Buff / 减伤(留后续模块)
    /// </summary>
    public class PlayerDataManager : Singleton<PlayerDataManager>
    {
        // 角色数据(序列化存储,可存档)
        private CharacterData _characterData = new CharacterData();

        // 公开只读属性
        public float CurrentHp => _characterData.CurrentHp;
        public float MaxHp => _characterData.MaxHp;
        public bool IsDead => _characterData.IsDead;

        // 日志标记
        private const string LOG_TAG = "Player";

        /// <summary>
        /// 初始化。在首次访问 Instance 时自动调用。
        /// </summary>
        protected override void Init()
        {
            // 确保初始状态有效
            if (_characterData.MaxHp <= 0f)
            {
                _characterData.MaxHp = 100f;
            }
            if (_characterData.CurrentHp <= 0f || _characterData.CurrentHp > _characterData.MaxHp)
            {
                _characterData.CurrentHp = _characterData.MaxHp;
            }
            _characterData.IsDead = false;

            AppLog.Info(LOG_TAG, $"PlayerDataManager initialized: {_characterData.CurrentHp}/{_characterData.MaxHp}");
        }

        /// <summary>
        /// 受到伤害的入口。由 TestRunner / 敌人 AI 调用。
        /// </summary>
        /// <param name="damage">伤害值(正数)</param>
        /// <param name="fromDirection">受击方向(用于受击动画选择)</param>
        public void TakeDamage(float damage, Vector3 fromDirection)
        {
            // 死亡后不再受伤
            if (_characterData.IsDead) return;
            // 无效伤害忽略
            if (damage <= 0f) return;

            _characterData.CurrentHp = Mathf.Max(0f, _characterData.CurrentHp - damage);

            // 死亡判定
            if (_characterData.CurrentHp <= 0f)
            {
                _characterData.IsDead = true;
                EventBus.Publish(new PlayerDiedEvent());
                AppLog.Info(LOG_TAG, $"Player died (damage={damage:F1})");
            }
            else
            {
                EventBus.Publish(new PlayerDamagedEvent(damage, _characterData.CurrentHp, fromDirection));
                AppLog.Info(LOG_TAG, $"Damaged -{damage:F1} HP={_characterData.CurrentHp:F1}/{_characterData.MaxHp:F1}");
            }
        }

        /// <summary>
        /// 重置为满血状态。供测试/复活用。
        /// </summary>
        public void ResetHealth()
        {
            _characterData.ResetToFull();
            AppLog.Info(LOG_TAG, $"Health reset: {_characterData.CurrentHp}/{_characterData.MaxHp}");
        }

        /// <summary>
        /// 供外部获取完整数据快照(存档时调用)。
        /// </summary>
        public CharacterData GetData() => _characterData;

        /// <summary>
        /// 加载数据快照(读档时调用)。
        /// </summary>
        public void LoadData(CharacterData data)
        {
            if (data == null)
            {
                AppLog.Warning(LOG_TAG, "LoadData: data is null, ignored");
                return;
            }
            _characterData = data;
            AppLog.Info(LOG_TAG, $"Data loaded: HP={_characterData.CurrentHp}/{_characterData.MaxHp}, IsDead={_characterData.IsDead}");
        }
    }
}
```

**设计要点**:
- 继承 `Singleton<PlayerDataManager>`,而非 `MonoBehaviour`
- 通过 `PlayerDataManager.Instance` 全局访问,无需挂载场景
- `Init()` 方法在首次访问时自动调用(由 Singleton 基类调用)
- `TakeDamage()` 保持原有逻辑:先扣血,再判断死亡
- `GetData()` / `LoadData()` 供未来存档系统使用

**注意**:需要检查 `Singleton<T>` 基类是否有 `Init()` 虚方法。如果当前基类没有,需要在 `PlayerDataManager` 中使用 `Awake()` 或直接在使用前初始化数据。

### Step 7.8.3 创建 PlayerFeedback.cs

**文件**:新建 `Assets/Scripts/Character/PlayerFeedback.cs`

```csharp
using Emberwild.Core.Events;
using UnityEngine;

namespace Emberwild.Character
{
    /// <summary>
    /// 角色受击反馈 — 订阅伤害/死亡事件,驱动 Animator 表现。
    /// 挂载在 Player 预制体上。
    ///
    /// 职责:
    /// - 订阅 PlayerDamagedEvent → Animator.SetTrigger("getHit")
    /// - 订阅 PlayerDiedEvent → Animator.SetTrigger("die")
    /// - 维护 isDead 状态,防止死亡后重复响应受伤
    ///
    /// 不做:
    /// - 不做伤害计算(PlayerDataManager 负责)
    /// - 不做输入锁定(留 7.9)
    /// </summary>
    public class PlayerFeedback : MonoBehaviour
    {
        [Header("依赖")]
        [SerializeField] private Animator _animator;

        [Header("Animator 参数名")]
        [SerializeField] private string _getHitTrigger = "getHit";
        [SerializeField] private string _dieTrigger = "die";

        // 状态
        private bool _isDead = false;
        private int _getHitHash;
        private int _dieHash;

        private void Start()
        {
            // 获取 Animator
            if (_animator == null)
            {
                _animator = GetComponent<Animator>();
                if (_animator == null)
                {
                    Debug.LogWarning("[PlayerFeedback] Animator not found on this GameObject.");
                }
            }

            // 缓存 Trigger 参数 hash
            _getHitHash = Animator.StringToHash(_getHitTrigger);
            _dieHash = Animator.StringToHash(_dieTrigger);

            // 订阅事件
            EventBus.Subscribe<PlayerDamagedEvent>(OnDamaged);
            EventBus.Subscribe<PlayerDiedEvent>(OnDied);
        }

        private void OnDestroy()
        {
            EventBus.Unsubscribe<PlayerDamagedEvent>(OnDamaged);
            EventBus.Unsubscribe<PlayerDiedEvent>(OnDied);
        }

        private void OnDamaged(PlayerDamagedEvent evt)
        {
            // 死了不再响应普通受伤
            if (_isDead) return;
            if (_animator == null) return;

            _animator.SetTrigger(_getHitHash);
        }

        private void OnDied(PlayerDiedEvent evt)
        {
            _isDead = true;
            if (_animator == null) return;

            _animator.SetTrigger(_dieHash);
        }

        /// <summary>
        /// 重置反馈状态。供复活系统调用。
        /// </summary>
        public void ResetFeedback()
        {
            _isDead = false;
        }
    }
}
```

**设计要点**:
- 挂载在 Player 预制体上(因为需要获取 Animator)
- `isDead` 状态在内部维护,不读取 `PlayerDataManager`(避免循环依赖)
- `ResetFeedback()` 供复活时调用

```csharp
using Emberwild.Character;
using Emberwild.Core.AppLog;
using UnityEngine;

namespace Emberwild.Test
{
    /// <summary>
    /// 受击系统测试脚本 — 空格键触发伤害,R 键重置 HP。
    /// 本 Stage 仅用于验证「伤害事件 → 扣血 → 受击动画」链路。
    /// 敌人 AI 攻击在后续阶段实现。

    {
        private void Start()
        {
            // PlayerDataManager 是 Singleton,直接访问 Instance
            if (PlayerDataManager.Instance == null)
            {
                AppLog.Error("Test", "TestRunner: PlayerDataManager.Instance is null.");
                enabled = false;
                return;
            }

            AppLog.Info("Test", "=== Stage 7.8: Hit System Test ===");
            AppLog.Info("Test", "SPACE: TakeDamage(10)  R: ResetHealth()");
        }

        private void Update()
        {
            // 空格:受到 10 点伤害
            if (Input.GetKeyDown(KeyCode.Space))
            {
                if (PlayerDataManager.Instance.IsDead)
                {
                    AppLog.Info("Test", "Player is dead, cannot take more damage");
                    return;
                }
                PlayerDataManager.Instance.TakeDamage(10f, Vector3.forward);
            }

            // R:重置 HP
            if (Input.GetKeyDown(KeyCode.R))
            {
                PlayerDataManager.Instance.ResetHealth();

                // 重置 PlayerFeedback 状态(如果存在)
                var feedback = FindObjectOfType<PlayerFeedback>();
                if (feedback != null) feedback.ResetFeedback();

                AppLog.Info("Test", "Health reset to full");
            }
        }
    }
}
```

**修改要点**:
- 移除 `[SerializeField] private PlayerDataManager _playerDataManager;`
- 改为直接调用 `PlayerDataManager.Instance`
- 移除 Start 中的引用获取逻辑
- R 键重置时通过 `FindObjectOfType<PlayerFeedback>()` 找到反馈组件

## 七、关键设计决策

| 决策点 | 选项 | 最终选择 | 理由 |
|--------|------|---------|------|
| PlayerDataManager 类型 | MonoBehaviour / Singleton\<T\> | **Singleton\<T\>** | 全局唯一访问点,无需场景挂载 |
| 数据模型 | 每属性一个组件 / 统一 CharacterData | **统一 CharacterData** | 兼容 JSON 存档,避免组件爆炸 |
| CharacterData 类型 | MonoBehaviour / 纯类 | **纯类** | JSON 直接序列化 |
| Animator 驱动 | PlayerDataManager / PlayerFeedback | **PlayerFeedback** | 职责分离 |
| 测试方式 | 10s 定时 / 手动空格触发 | **手动空格触发** | 更可控 |
| 受击方向 | 左/右/前/后四种 / 统一一种 | **统一一种** | 简化本 Stage |
| 死亡后锁定输入 | 是 / 否 | **否(留 7.9)** | 本 Stage 专注链路打通 |
