# 15. 阶段五手把手实现手册（小螃蟹 AI —— 行为树升级）

> 配套：`14.阶段五行为树升级策划方案.md`
> **本阶段目标**：把决策逻辑从 8 个状态类收敛到一棵行为树，实现"决策与执行分离"。
> **关键认知**：本阶段**不加新功能、不改螃蟹的可见行为**——它是一次"决策层重构"。做完后螃蟹行为与前四阶段完全一致，但决策逻辑集中、可扩展、换怪零改动。

## 步骤 1：新建行为树框架（5 个文件）

**为什么？** 行为树的核心是两类节点：**组合节点**（Selector 优先级选择、Sequence 顺序执行）和**叶子节点**（Condition 条件、Action 动作）。先搭好这套积木，决策树就能用它们拼出来。

### 1.1 `BTNode.cs`（抽象基类 + 三态）

新建 `Assets/Scripts/AI/BT/BTNode.cs`：

```csharp
using Emberwild.AI.Enemy;

namespace Emberwild.AI.BT
{
    /// <summary>节点运行状态:Running(进行中) / Success(成功) / Failure(失败)。</summary>
    public enum NodeState { Running, Success, Failure }

    /// <summary>
    /// 行为树节点基类。每帧被 Evaluate,返回三态之一。
    /// 本阶段直接以 EnemyBrain 为上下文,保持简单;未来要通用可抽成泛型。
    /// </summary>
    public abstract class BTNode
    {
        public abstract NodeState Evaluate(EnemyBrain brain);
    }
}
```

### 1.2 `Condition.cs`（条件叶子）

新建 `Assets/Scripts/AI/BT/Condition.cs`：

```csharp
using System;
using Emberwild.AI.Enemy;

namespace Emberwild.AI.BT
{
    /// <summary>条件叶子:用委托判断黑板/状态,返回 Success / Failure。</summary>
    public class Condition : BTNode
    {
        private readonly Func<EnemyBrain, bool> _predicate;

        public Condition(Func<EnemyBrain, bool> predicate)
        {
            _predicate = predicate;
        }

        public override NodeState Evaluate(EnemyBrain brain)
        {
            return _predicate(brain) ? NodeState.Success : NodeState.Failure;
        }
    }
}
```

### 1.3 `ActionNode.cs`（动作叶子）

新建 `Assets/Scripts/AI/BT/ActionNode.cs`：

```csharp
using Emberwild.AI.Enemy;
using Emberwild.AI.Enemy.State;

namespace Emberwild.AI.BT
{
    /// <summary>
    /// 动作叶子:切换到目标状态并持续执行。
    /// ChangeState 内部有"同状态保护",重复调用无害;动作的"完成→切走"由状态类自己负责。
    /// </summary>
    public class ActionNode : BTNode
    {
        private readonly EnemyStateType _stateType;

        public ActionNode(EnemyStateType stateType)
        {
            _stateType = stateType;
        }

        public override NodeState Evaluate(EnemyBrain brain)
        {
            brain.ChangeState(_stateType);
            return NodeState.Running;   // 动作持续进行中
        }
    }
}
```

### 1.4 `Selector.cs`（优先级选择）

新建 `Assets/Scripts/AI/BT/Selector.cs`：

```csharp
using System.Collections.Generic;
using Emberwild.AI.Enemy;

namespace Emberwild.AI.BT
{
    /// <summary>优先级选择:从左到右,返回第一个非 Failure 的子节点结果。</summary>
    public class Selector : BTNode
    {
        private readonly List<BTNode> _children;

        public Selector(params BTNode[] children)
        {
            _children = new List<BTNode>(children);
        }

        public override NodeState Evaluate(EnemyBrain brain)
        {
            foreach (var child in _children)
            {
                var state = child.Evaluate(brain);
                if (state != NodeState.Failure)
                    return state;   // Running 或 Success
            }
            return NodeState.Failure;
        }
    }
}
```

### 1.5 `Sequence.cs`（顺序执行）

新建 `Assets/Scripts/AI/BT/Sequence.cs`：

```csharp
using System.Collections.Generic;
using Emberwild.AI.Enemy;

namespace Emberwild.AI.BT
{
    /// <summary>顺序节点:从左到右,全部 Success 才 Success,遇 Failure/Running 即停。</summary>
    public class Sequence : BTNode
    {
        private readonly List<BTNode> _children;

        public Sequence(params BTNode[] children)
        {
            _children = new List<BTNode>(children);
        }

        public override NodeState Evaluate(EnemyBrain brain)
        {
            foreach (var child in _children)
            {
                var state = child.Evaluate(brain);
                if (state != NodeState.Success)
                    return state;   // Failure 或 Running
            }
            return NodeState.Success;
        }
    }
}
```

**✅ 预期结果**：编译通过（此时还没人用它们，正常）。

**❓ 排查**：报 `EnemyBrain 找不到` → 确认 5 个文件顶部都 `using Emberwild.AI.Enemy;`。

## 步骤 2：黑板加 `LastHitTime`

**为什么？** 受击现在靠事件直接 `ChangeState(Hit)`。本阶段改为事件只写"受击时间戳"，行为树用条件"`Time.time - LastHitTime < 硬直时长`"判断是否进 Hit。所以黑板需要一个时间戳字段。

**文件**：`Assets/Scripts/AI/Enemy/EnemyBlackboard.cs`

在 `LastRollTime` 后面加：

```csharp
        /// <summary>
        /// 最近一次受击时间(行为树据此判断是否处于受击硬直)
        /// </summary>
        public float LastHitTime = -999f;
```

> `-999f` 是"很久以前"的哨兵值，确保开局不会误判成"正在受击"。

**✅ 预期结果**：编译通过。

## 步骤 3：`IdleState` 移除内部决策

**为什么？** "看到目标就追"是**优先级决策**，现在归行为树（Chase 条件"能看到目标"）。待机状态只剩"执行"（刹车 + 归零动画）。

**文件**：`Assets/Scripts/AI/Enemy/State/IdleState.cs`

把 `OnUpdate` 里那段决策删掉，改成空实现：

```csharp
        public void OnUpdate(EnemyBrain brain)
        {
            // 决策交给行为树,待机本身不做任何事
        }
```

（`OnEnter` 的 `Stop()` + `SetMoveSpeed(0)` 和 `OnExit` 保持不变。）

## 步骤 4：`ChaseState` 移除内部决策

**为什么？** 原来的 `ChaseState.OnUpdate` 是一串 if-else（残血/近战/滚动/远程/丢目标），这些**全部是决策**，搬到行为树。追击状态只留"执行"（持续下达目标坐标 + 驱动动画）。

**文件**：`Assets/Scripts/AI/Enemy/State/ChaseState.cs`

**整体替换** `OnUpdate` 为：

```csharp
        public void OnUpdate(EnemyBrain brain)
        {
            // 只执行追击,决策交给行为树
            if (brain.BB.Target != null)
            {
                brain.Agent.SetDestination(brain.BB.Target.position);
                brain.Animator.SetMoveSpeed(brain.NormalizedSpeed);
            }
        }
```

（`OnEnter` / `OnExit` 保持不变。）

> 注意：`ChaseState` 顶部若已无 `using UnityEngine;`，`Time` 已不再使用可删，但保留也无害。

## 步骤 5：`EnemyBrain` 接入行为树（🔴 核心）

**文件**：`Assets/Scripts/AI/Enemy/EnemyBrain.cs`

改 6 处：

**① 顶部加 using**：

```csharp
using Emberwild.AI.BT;              // ← 新增
using Emberwild.AI.Enemy.State;
```

**② 加字段**（放在 `_states` 字典附近）：

```csharp
        /// <summary>行为树根节点(每帧决策)。</summary>
        private BTNode _root;
```

**③ `Awake` 里构建行为树**（放在注册状态之后）：

```csharp
            _states[EnemyStateType.Hide] = new HideState();

            // 构建行为树(决策层)
            _root = BuildTree();
```

**④ `Update` 改为"行为树决策 + 状态执行"**：

```csharp
        private void Update()
        {
            if (!_initialized) return;
            _perception.Tick(BB);            // 1. 感知写黑板
            _root.Evaluate(this);            // 2. 行为树决策(按优先级切状态)
            _currentState?.OnUpdate(this);   // 3. 状态执行
        }
```

**⑤ `OnDamaged` 只写黑板、不再直接切状态**：

```csharp
        private void OnDamaged(EnemyDamagedEvent evt)
        {
            if (!_initialized) return;
            if (evt.Victim != (ICombatEntity)_entity) return;

            BB.HpRatio = Entity != null ? evt.CurrentHp / Entity.MaxHp : 1f;
            BB.LastHitTime = Time.time;   // 标记受击时间,行为树据此进 Hit
            // 不再直接 ChangeState(Hit),决策交给行为树
        }
```

**⑥ 移除 `OnDied` 订阅与方法**（死亡由行为树的 `IsDead` 条件检测）：

把 `OnEnable` / `OnDisable` 改成只订阅 `EnemyDamagedEvent`：

```csharp
        private void OnEnable()
        {
            EventBus.Subscribe<EnemyDamagedEvent>(OnDamaged);
        }

        private void OnDisable()
        {
            EventBus.Unsubscribe<EnemyDamagedEvent>(OnDamaged);
        }
```

并**删除** `OnDied` 方法。

**⑦ 加 `BuildTree()` 方法**（放在类末尾，`OnDamaged` 之后）：

```csharp
        /// <summary>
        /// 构建决策树:8 个状态的优先级(从上到下,命中即停)。
        /// 顺序:死亡 > 受击 > 缩壳 > 近战 > 滚动 > 远程 > 追击 > 待机。
        /// </summary>
        private BTNode BuildTree()
        {
            return new Selector(
                // 1. 死亡(最高优先级,终止)
                new Sequence(
                    new Condition(b => b.Entity != null && b.Entity.Attribute != null && b.Entity.Attribute.IsDead),
                    new ActionNode(EnemyStateType.Dead)
                ),
                // 2. 受击硬直
                new Sequence(
                    new Condition(b => Time.time - b.BB.LastHitTime < b.HitStunDuration),
                    new ActionNode(EnemyStateType.Hit)
                ),
                // 3. 缩壳(残血)
                new Sequence(
                    new Condition(b => b.BB.CanSeeTarget && b.BB.HpRatio < b.HideHpThreshold),
                    new ActionNode(EnemyStateType.Hide)
                ),
                // 4. 近战
                new Sequence(
                    new Condition(b => b.BB.CanSeeTarget && b.BB.DistanceToTarget <= b.MeleeRange),
                    new ActionNode(EnemyStateType.AttackMelee)
                ),
                // 5. 滚动冲刺(中距离 + 冷却)
                new Sequence(
                    new Condition(b => b.BB.CanSeeTarget
                        && b.BB.DistanceToTarget >= b.RollMinRange && b.BB.DistanceToTarget <= b.RollMaxRange
                        && Time.time - b.BB.LastRollTime >= b.RollCooldown),
                    new ActionNode(EnemyStateType.RollChase)
                ),
                // 6. 远程攻击(中远距离 + 冷却)
                new Sequence(
                    new Condition(b => b.BB.CanSeeTarget
                        && b.BB.DistanceToTarget >= b.RangedMinRange && b.BB.DistanceToTarget <= b.RangedMaxRange
                        && Time.time - b.BB.LastAttackTime >= b.AttackCooldown),
                    new ActionNode(EnemyStateType.AttackRanged)
                ),
                // 7. 追击
                new Sequence(
                    new Condition(b => b.BB.CanSeeTarget),
                    new ActionNode(EnemyStateType.Chase)
                ),
                // 8. 待机(兜底)
                new ActionNode(EnemyStateType.Idle)
            );
        }
```

**✅ 预期结果**：编译 0 报错。

**❓ 排查**：
- 报 `Selector / Condition / ActionNode 找不到` → 确认步骤 1 的 5 个文件建在 `Assets/Scripts/AI/BT/`、命名空间 `Emberwild.AI.BT`，且 5.① 的 using 加对了。
- 报 `OnDied 未定义` 但 `OnDisable` 还在引用它 → 确认 5.⑥ 删干净了 `OnDied` 和它的订阅。

## 步骤 6：端到端回归验收

行为树是**决策重构**，验收 = 全量回归（螃蟹行为与前四阶段一致）：

1. `Spawner` 的 `Max Enemies` 设 10，Play。

**逐条勾选：**

- [ ] 玩家走进视野 → `Shell → Chase` 追击
- [ ] 贴脸 → `Shell → AttackMelee` 咬、玩家掉血
- [ ] 4~8m → `Shell → AttackRanged` 远程、玩家掉血
- [ ] 3~7m → `Shell → RollChase` 滚动冲刺
- [ ] 打残血 → `Shell → Hide` 缩壳 + 减伤
- [ ] 打一下 → `Shell → Hit` 受击打断；打死 → `Shell → Dead` 死亡动画
- [ ] 多怪同场 → 各打各的、各死各的
- [ ] Console 全程无报错、无状态抖动

**架构验收**：打开 `EnemyBrain.BuildTree()`，你能在一棵树上读完 8 个状态的优先级——这就是"决策集中"的直观体现。

## 步骤 7：报错对照表

| 现象 | 原因 | 修法 |
| -- | -- | -- |
| 螃蟹不追了 | ChaseState 决策删了但行为树没建/没 Evaluate | 步骤 5④ 检查 Update |
| 开局就进 Hit | `LastHitTime` 初始值不是负值 | 步骤 2 设 `-999f` |
| 打一下就不打了 | AttackMeleeState 的"硬直结束→Chase"被误删 | 确认该状态类没动（本阶段不改它） |
| 受击不打断 | OnDamaged 没写 LastHitTime / 行为树 Hit 条件错 | 步骤 5⑤ 与 BuildTree 第 2 条 |
| 死亡没反应 | OnDied 被删后行为树 Dead 条件没生效 | 检查 `Entity.Attribute.IsDead` 条件 |
| 状态反复横跳 | 优先级顺序错 | 对照 BuildTree 注释的顺序 |
